Implement ONE Python module scripts/d1_single_step_geometry.py for a fixed native MuJoCo plane + single axis-aligned 15 mm box qualification. No tools; no simulation or tests execution. Return one fenced Python block only. Root will integrate/test. Target Python 3.10, numpy, mujoco. Keep under ~250 lines. Strictly geometry/read-only, never mj_step, mj_forward, mutation or hidden data construction.

Required API:
1. collision_identity(model, geom_id) -> str. Use actual geom name if present; otherwise stable canonical body NAME plus the ordinal of that geom among ALL body's geoms (not global ID). Must map identical anonymous robot geoms across box insertion ID shifts.
2. robot_collision_ids(model) -> tuple[int,...]: all model.geom_bodyid > 0 AND either contype != 0 or conaffinity != 0. Exclude visual decorations and world terrain. Do not use visual meshes to decide crossing.
3. geom_world_bounds(model, data, geom_id) -> tuple[np.ndarray,np.ndarray]. Geometry positions/orientations already provided in data.geom_xpos / data.geom_xmat. Compute exact world AABB for sphere, ellipsoid, capsule, cylinder and box using compiled type/size. Cylinder axis is local z: support radius along world axis i is halfheight*abs(R[i,2]) + radius*sqrt(R[i,0]^2+R[i,1]^2); capsule radius + halfheight*abs(R[i,2]); box abs(R)@halfsize; ellipsoid sqrt(sum((R*size)^2,axis=1)). Reject unsupported collision types with ValueError instead of guessing mesh radius. Read compiled sizes, not nominal wheel radius. Validate finite proper shape inputs as useful; no speculative framework.
4. robot_collision_bounds(model,data) -> list of JSON serializable dicts: geom_id, identity, body_name, geom_type(int), minimum_world_m, maximum_world_m, margin_m, wheel_index (0 FL_foot,1 FR_foot,2 RL_foot,3 RR_foot or None). Only physical robot geoms.
5. box_contact_feature(position_world_m, normal_box_to_robot_world, center_world_m, half_size_m, *, tolerance_m) -> dict. Axis-aligned box, normalized input normal required within 1e-6; finite position etc. Recognize supporting face/edge/corner from nonzero normal axes (abs>1e-6): face signs x-/x+/y-/y+/z-/z+ mapped to front/back/right/left/bottom/top. Feature name e.g. front, top, front_top_edge, front_left_top_corner. Check that contact position is within tolerance of each supporting box coordinate and within the full box bounds expanded tolerance. Return feature, geometric_support_valid bool, supporting_faces list, support_offsets_m list (abs position minus corresponding box support coordinate), normalized normal list. Correct front horizontal normals (-1,0,0) and front-top diagonal are valid. Do not assert every terrain normal vertical. Zero normal, NaNs, negative tolerance reject. Contact position is native solver cache, not synchronized endpoint; no force claims here. Position tolerance is caller-owned, derived from actual contact dist/margin, never a force threshold.

Document limitations: AABB crossing only proves sampled pose support bounds, no continuous-time penetration guarantee. Box feature helper interprets normal already corrected by geom order, does not solve contacts or certify positive load. No imports from flat-plane clearance helpers, no CLI.

MuJoCo enum types are available via mujoco.mjtGeom. All original D1 wheels use collision cylinders radius .087 halfheight .02; visuals are meshes but excluded. Other robot collisions may be primitives. Name-based identity must account for mostly unnamed imported robot geoms. Source model default joint order FL/FR/RL/RR and joints hip/thigh/calf/foot. Keep return types consistent.
