# 八维轮腿动作的实际响应

当前低层在固定平地上完成了四条腿和四个轮子的正负动作探针。加入有界偏航速度反馈后，左右转角达到命令积分的约 76.7%，末秒偏航速度 RMSE 约 0.0228 rad/s。20 ms 传感器延迟下仍会跌倒，不能用这批结果支持延迟鲁棒性或真机部署。

最新完整记录在 [yaw4_final_channels](yaw4_final_channels/)，20 个确定性开发案例全部执行完毕，16 个逐通道正负响应均通过。没有训练 RL，没有改变地面摩擦。全部使用 `sampling_mode="synchronized"`。

## 当前的偏航反馈

名义轮速使用一个有界的偏航请求：

```text
yaw_request = clip(yaw_command + gain*(yaw_command - measured_body_yaw_rate), -0.6, 0.6)
wheel_speed_i = (forward_command - yaw_request*lateral_offset_i) / 0.087
```

`gain` 无量纲，角速度单位为 rad/s。`nominal_targets()` 仍是纯计算，既不读取运行 plant，也不更新积分。`effective_yaw_request_rps` 在目标与执行报告中都有记录。这个反馈补偿了当前闭环的部分欠转，没有把理想滚动公式当作精确的四轮滑移模型。

轮速 PI 保持 P=2.2、I=3，其余支撑参数与地形不变。新的开发目标独立于旧 25% 门槛：转角至少达到命令积分的 70%，末秒 yaw RMSE ≤0.05 rad/s。

| 偏航反馈 gain | 左 / 右转角比例 | 左 / 右末秒 yaw RMSE rad/s | 新目标 |
|---|---:|---:|---|
| 0 | 30.66% / 30.67% | 0.09193 / 0.09191 | 未通过 |
| 2 | 64.54% / 64.55% | 0.03587 / 0.03584 | 转角不足 |
| 4 | 76.70% / 76.71% | 0.02277 / 0.02277 | 通过 |
| 6 | 82.85% / 82.85% | 0.01555 / 0.01558 | 通过 |

默认采用先达到目标的 gain=4。实际左右转角为 +0.776039/-0.776097 rad，命令积分为 ±1.01175 rad，仍有约 23% 的转角不足。左右末秒前向速度 RMSE 为 0.005698/0.005679 m/s。

启停案例最后 1 s 的速度 RMSE 从 gain=0 时的 0.138470 变成 gain=4 时的 0.138455 m/s；分段误差也保存在 summary，未发现超过预定 10% 相对幅度的退化。这个刹车过渡仍不够好，偏航反馈没有解决它。

传感器测试使用实际 IMU/编码器融合和估计地面，测量噪声 seed=17。gain=4、零测量延迟下，左右转角比例为 76.79%/76.68%，也通过上述门槛。噪声幅值只是开发示例，并非来自硬件辨识。

加入 20 ms 测量延迟后，gain=4 左右转向分别在 4.10/3.27 s 跌倒；同样延迟、gain=0 的对照也在 7.58/3.73 s 跌倒。延迟失败不能全部归因于新偏航反馈，但 gain=4 在这两个案例中更早跌倒，不能隐去。提前结束的 RMSE 只描述已执行前缀，不能与完整八秒 RMSE 直接比较。[零延迟](yaw4_sensor_delay0/)与[延迟结果](yaw4_sensor_delay2/)分开保存，[无偏航反馈的延迟对照](yaw0_sensor_delay2/)也保留。

## 无偏航反馈的开发过程

以下保留 [wheel_pi_2p2_3p0](wheel_pi_2p2_3p0/) 的 20 个案例和更早的 P 增益比较，解释为什么后来需要外层偏航反馈。其中 16 个是逐通道正负动作，另外四个检查零动作站立、启停和左右转向。旧结果没有重新命名为新控制器的成绩。

### 动作如何进入动力学

顺序固定为 `FL / FR / RL / RR`。前四个动作的满量程是 ±0.04 m 腿伸缩，正值使轮心相对机体向下；后四个满量程是 ±4 rad/s 轮速。此次通道探针采用 ±0.5 动作，从第 1 s 开始用 0.5 s 线性过渡到目标，即 ±20 mm 和 ±2 rad/s。

腿部用独立名义模型预先计算伸缩 IK 表，保持轮心的名义机体系 x/y；控制时插值为关节目标。扭矩只组合一套腿关节 PD 与重力、姿态支撑项，轮关节单独使用轮速 PI。没有叠加旧 LQR/VMC，也没有借助运行 plant 查询未提供的状态。

`D1Command.base_height_m` 仍指世界高度，控制器显式减去调用方给出的 `ground_height_m` 得到净空。腿动作在此基础上增加伸缩，不抵消名义高度命令。地面估计如何产生由上层状态源负责。

轮速 PI 使用 `kp=2.2 N·m/(rad/s)`、`ki=3 N·m/rad`，每轮积分限于 ±4 N·m，扭矩限于 ±12 N·m。输出已饱和且误差继续推向饱和方向时，积分不再增加。`control_memory` 报告四轮积分，`last_result.memory_before/after` 区分本拍更新前后；`nominal_targets()` 只计算目标，不推进积分。每个控制周期只能调用一次 `compute()`。

腿关节目标受原有关节位置范围约束，相对当前测量位置的目标增量不超过额定速度乘周期。速度或位置边界处会移除朝限外的扭矩。这是命令侧保护，不能保证外力冲击下的实际关节速度永不越限；CSV 单独记录实际速度和越限量。

### 轮速积分改善了多少

| 轮速控制 | 左 / 右实际转角 rad | 命令转角比例 | 末秒 yaw RMSE rad/s |
|---|---:|---:|---:|
| P=0.55，I=0 | +0.03397 / -0.03398 | 约 3.36% | 0.14627 / 0.14627 |
| P=2.2，I=0 | +0.11424 / -0.11438 | 11.29% / 11.30% | 0.13618 / 0.13618 |
| P=8.8，I=0 | +0.02515 / -0.02360 | 2.49% / 2.33% | 0.14639 / 0.14877 |
| P=2.2，I=3 | +0.31017 / -0.31028 | 30.66% / 30.67% | 0.09193 / 0.09191 |

命令积分为 ±1.01175 rad，末段命令偏航角速度为 ±0.15 rad/s。最初轮速 P=0.55 的实际转向测试失败，随后保持地图与支撑控制不变，只改轮速比例增益。P=8.8 时短周期速度振荡增大，转向反而变差。再在 P=2.2 的基线上单独加入积分，左右转向才通过“至少完成 25% 命令转角、末秒 yaw RMSE ≤0.10 rad/s”的开发门槛。门槛用于排除几乎不转弯的情况，不是精准轨迹跟踪要求。

前三组原始记录保存在 [development_v1](development_v1/)、[wheel_gain_2p2](wheel_gain_2p2/) 和 [wheel_gain_8p8](wheel_gain_8p8/)。每组都保留当时的源码归档，旧记录里的 `stand_quality_pass` 只检查站立高度/姿态，不能拿它判断转向合格。

末段左转的前左轮目标为 1.3577 rad/s，实际为 1.4121 rad/s；前右轮为 2.1142 与 2.0324 rad/s，没有触发轮扭矩限幅。此时机体 yaw rate 仅为 0.05990 rad/s。轮速已接近目标，机体角速度仍偏低，后续需要研究四轮滑移与外层转向反馈，不能只继续加大轮速比例增益。

### 当时的其余响应与限制

零动作站立末秒高度 RMSE 为 5.54 mm。四条腿施加 ±20 mm 目标后，对应轮心相对机体的实际变化为约 10.3–12.1 mm，方向均正确。机体姿态与其他支撑腿会一起变化，不能把目标位移当成已经精确执行的位移。

轮通道施加 ±2 rad/s 残差后，对应轮速相对零动作的末秒变化为约 1.26–1.57 rad/s，八个正负案例方向全部正确。[summary.json](wheel_pi_2p2_3p0/summary.json) 保存 16 个逐通道响应检查及原始差值。当前全通道试验只覆盖半量程，尚未证明任意八维动作组合都稳定。

左右转向末秒前向速度 RMSE 分别为 0.000683 和 0.000701 m/s。启停案例在第 7 s 从 -0.25 m/s 阶跃到零，最后 1 s 的速度 RMSE 为 0.13847 m/s，包含刹车过程，仍需改善。不能只挑最终一拍速度接近零的数值。

20 个案例均未出现关节位置越限，最高关节速度约为额定值的 10.42%。控制计算中位耗时约 0.31 ms；这是本机进程内的开发测量，不包含传感器或执行器通信，不提供硬件实时性保证。

## 接入与复核

```python
controller = D1WheelLegController(control_dt=0.01)
nominal = controller.nominal_targets(command, state, ground_height_m=estimated_ground)
memory_before = controller.control_memory
# 上层将 nominal 和 memory_before 放入本拍策略观测，再计算 action8。
torque = controller.compute(command, state, action8, ground_height_m=estimated_ground)
# 16 维 torque 交给统一 runtime 的执行器；不要再叠旧 VMC/腿 PD。
```

```bash
rtk env PYTHONPATH=src:.local-deps OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  python3 -m pytest tests/test_d1_wheel_leg_controller.py -q
rtk env PYTHONPATH=src:.local-deps OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  python3 scripts/probe_d1_wheel_leg_actions.py --output results/my_v3_action_probe
```

输出目录必须不存在。CSV 的目标对应 `target_time_s`，真值状态对应下一次同步时刻 `truth_time_s`，相差 10 ms；`measurement_time_s` 则记录控制器实际消费的测量时刻，延迟组不能把它当作当前时刻。每轮的积分和限幅标志均保留。源码运行中未变，哈希与静态资产哈希写入协议，产物另有 manifest。完整动作通道成绩来自真值状态源；传感器专项另行标明。统一 runtime 加入非理想执行器后的结果还需单独报告。

[独立复算](independent_audit.json)检查了全部 96 个回合、51468 个控制步，核对 132 个产物哈希和 92 个归档源码哈希。它不导入控制器或探针脚本，从 CSV 重新计算速度/高度 RMSE 与转角，最大差为 `5.55e-17`，并核对实际终止、测量延迟和 70% 判据。运行 `python3 results/d1_v3_action_probes/audit_results.py` 可重新检查已保存记录。

IK 查表函数使用了 Claude Opus 辅助草稿，随后修正接口名和返回结构，并增加独立 FK 及状态恢复检查。所有结果由实际仿真生成。调用提示和会话日志仅作本地工作记录，不随实验数据发布。
