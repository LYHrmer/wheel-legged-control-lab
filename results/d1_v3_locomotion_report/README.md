# 命令条件 PPO：固定预算对照

八维轮腿残差在两条留出道路上降低了平均速度误差，但不是全指标改善。相对于同一个八维零残差控制器，三个训练种子的平均速度 RMSE 从 0.04016 降到 0.03328 m/s；高度 RMSE 增加约 1.92 mm，机械活动量增加约 4.47 W。当前证据支持继续研究这个动作接口，不支持“RL 已全面超过传统控制”或“已具备 sim2real 能力”。

## 实验设置

- 两个控制结构：两维 LQR 力残差、八维腿伸缩/轮速残差。每种结构都有自己的零残差对照。
- 训练 seed 为 24000、25000、26000；每个模型固定 32768 个样本，四个并行环境、64 次 PPO 更新调用。共 196608 个训练样本。
- 训练使用四张固定道路；开发和留出各两张道路。所有评测为 60 s 的连续命令，包括前进、后退、停车、转向和净空变化。
- 使用同步采样、oracle 状态源、单帧 82 维观测。没有用留出结果选 checkpoint；均加载预算末端模型。
- 协议在训练前记录于 [d1_v3_locomotion_protocol.json](../d1_v3_locomotion_protocol.json)。模型、分项奖励、原始动作和更新记录位于 [训练目录](../d1_v3_locomotion_ppo/)。

两个结构同时改变了低层控制，不能把两者差异全部归因于动作维数。计算 RL 收益时，必须在同一种控制器内做有无策略的配对比较。

## 留出道路结果

| 控制方式 | 速度 RMSE m/s | 偏航 RMSE rad/s | 高度 RMSE mm | 姿态 RMSE rad | 机械活动量 W | 质量达标 |
|---|---:|---:|---:|---:|---:|---:|
| LQR 零残差 | 0.07969 | 0.05684 | 15.30 | 0.01468 | 47.44 | 1/2 道路 |
| LQR + PPO | 0.08482 | 0.05372 | 15.99 | 0.01614 | 44.63 | 2/6 种子×道路 |
| 轮腿零残差 | 0.04016 | 0.03265 | 9.84 | 0.01802 | 16.03 | 2/2 道路 |
| 轮腿 + PPO | 0.03328 | 0.03055 | 11.76 | 0.02400 | 20.50 | 6/6 种子×道路 |

所有运行都完成了 60 s，因此这里的误差可以按同一时长比较。轮腿 PPO 的速度误差在六个配对中有五个减少，高度误差和机械活动量在六个配对中都增加。LQR PPO 在开发道路上有改善，但未稳定迁移到留出道路：开发达标 5/6，留出仅 2/6。这项退化保留在结果中。

固定 oracle 下，同一路面的两个评测 seed 产生了逐字节相同的 CSV 和 NPZ；它们只是重复标签，不是独立复现。审计器核对轨迹相同后才合并。这里仍然只有三个独立训练种子、每个 split 两张不同道路，不给置信区间，也不把 6000 个时间步当作 6000 个样本来做显著性检验。

## 地形曝光的限制

策略和零残差实际走过的路径并不相同。例如固定 seed 24000 在留出 S 弯道路上的非平地曝光比例约 51.1%，零残差约 67.3%；非平地路程分别约 3.63 m 和 4.13 m。因此“命令和地图相同”不等于“走过完全相同的地形轨迹”。

曝光阈值检查机身/轮心投影处的高度和坡度；它不证明每个轮子都保持接触，也不证明机器人穿越了整张地图。机械活动量为平均 `sum(abs(torque * velocity))`，不是电池功率。

## 核对原始记录

[独立复算脚本](../../scripts/audit_d1_locomotion.py)只使用 NumPy 和标准库，不导入仿真器或训练框架。它从 CSV/NPZ 重算 RMSE、动作量、轨迹长度和曝光计数，检查完整案例矩阵、终止原因、初始位置、来源压缩包以及源码摘要。摘要相同只说明字节一致，不是独立来源认证；机械功率和几何曝光标签仍来自原记录，不在审计器里重新仿真。

```bash
python scripts/audit_d1_locomotion.py --matrix-root results \
  --output results/my_phase4_arithmetic.json
```

审计器只创建新文件，不覆盖原记录。逐模型、逐道路结果和实际曝光会一起写入 JSON；不要只摘平均速度一列作为结论。

本次完整复算已通过，输出见 [arithmetic_audit.json](arithmetic_audit.json)。对应的
[审计测试](../../tests/test_d1_locomotion_audit.py)包含手算小样本、损坏 CSV/NPZ、来源压缩包
校验，以及把非零动作伪装成零残差的反例。未知的案例指标字段也会被拒绝，避免未经检查的
“成功率”等结论混进审计输出。

训练记录还通过了[384 次 PPO 更新的独立数值复算](ppo_math_audit.json)，包括完整 rollout 的
GAE 边界、原始 Gaussian 动作概率以及相邻更新的参数摘要。它没有重放优化器，不证明策略效果。
对应脚本为 [audit_d1_ppo_math.py](../../scripts/audit_d1_ppo_math.py)。

## 已知限制：20 ms 测量延迟

同一轮腿零残差控制器使用 IMU/编码器融合，开发道路无延迟时四个案例均完成并达标。整包测量增加 20 ms 延迟后，四个案例分别在 2.05、1.20、0.91、4.41 s 失稳；所有案例的非平地曝光都是零。记录在 [延迟诊断目录](../d1_v3_delay_diagnosis/)。

后续[九模型延迟对照](../d1_v3_delay_ablation/README.md)已完成，增加历史与本次随机化训练
仍未带来跨训练 seed 的稳定改善。那批实验使用诊断后的低层参数，不并入本页 oracle 留出成绩。

后续轮速增益对照保留了一个反例：`Kp=0.55, Ki=1.5, yaw_gain=4` 在平面短探针上完成左右
8 s 转向，进度 70.83%/70.71%；同配置、20 ms 延迟的完整开发任务仍然 4/4 失败，终止于
1.70、3.02、1.86、2.62 s。无延迟对照则 4/4 完成且达标。上述调参只用了开发条件，未重选
本页的 oracle 留出 checkpoint，也没有改动其默认 `2.2/3.0/4` 控制增益。
