# C35 连续侧向速度主任务：Astra 设计裁决

状态：设计草案，不是执行 GO；不授权控制器、模型、训练或物理运行。C34 独立完整读回确认首场 8.83 s 比 C33 的 9.37 s 缩短 5.76%，原物理与任务门通过，但终点误差 11.4568 mm、保留率 0.95985 未通过外部质量门，已按合同停止。仅一场左向；右向、β=1、40 mm 未尝试，保留原 C33 β=0 合格对照。此后不再扫 β，也不训练策略寻找更好的常数 β。

## 主任务与规模

主任务从“承诺完成一次 30 mm 四腿宏”改为“持 A/D 时持续跟踪侧向速度，松键后安全停止，停稳再反向”。侧移期间不在每个 30/40 mm 边界归零身体参考、重置模型或交回 B22。速度积分给出明确的目标轨迹，超调不增加合格吞吐。输入沿独立侧移意图通道进入单一控制 owner，不能把非零 vy 塞进拒绝该字段的旧 B22 99D 编码器；B22 参数保持冻结。

下一合同的设计目标应为稳定持续速度至少 **0.02 m/s**，发展目标 0.03–0.04 m/s；这是相对目前约 0.0032 m/s 的数倍工程目标，不是替用户定义“流畅”的验收线，也不保证现有硬件限幅下可达。验证要覆盖双向持键、停止和反向；报告整段与稳态速度、跟踪误差、停稳延迟、停止距离及保持。节约一两秒而仍处于 0.004–0.006 m/s，只能说明局部机制，不结束用户目标。

## 为什么不继续把旧宏包装成连续模式

当前固定 profile 的 `distance_scale=1`、`adaptive_swing=True`，四腿串行、卸载至少 0.12 s、加载至少 0.15 s、水平五次曲线峰速 0.16 m/s；lower 接触切换要求 t > 0.4×0.26=0.104 s。即使乐观地把身体位移、抬脚等待和 touchdown dwell 全部视为免费，沿用这些顺序和 D≤0.04 m，仍有

T ≥ 4×[0.12 + 1.875D/0.16 + 0.104 + 0.15]。

D=0.04 m 时 T≥3.371 s，即名义 D/T≤0.01187 m/s。真实轮形净空、升降、承载等待和身体运动只会增加时间。这是旧阶段顺序及参考速度公式的条件上界，不是机器人动力学定理；它已经说明只让身体在旧单腿脚相期间续行，不足以支持上述最低速度目标。源码锚点为 `scripts/d1_fast_side_step.py` 的配置、lower/contact 与 load 分支；现有 C31 水平时间同样采用 1.875D/0.16。若改变脚速、步长或脚相重叠，该界也随权限改变，不能继续引用为新任务证明。

因此主线应是一个**持续身体速度参考＋显式接触相位调度器**。数据接口支持一组摆动腿而非一个固定 leg_index。首先评估对角支撑两相交替、无腾空的可行性；这是扩大接触调度权限的新控制器，不是已合格 C34 的补丁。旧单腿方式保留为退回模式与对照。若两腿支撑在原关节、扭矩、轮形与姿态约束下不可行，应明确停止这一候选，改审步长／脚速／三维脚轨迹的有效权限；不要回到几组 β 或无效小残差训练。

## 安全声明分开写

可原样保留：同一模型与原生 dt、每控制五个 native 子步的完整记录；无非轮碰撞；身体姿态和高度、关节速度和范围、真实电机扭矩限幅；摆动轮水平运动的整轮净空与接触证据；IK 和力分配的有限性；异常落地、四足承载停稳后交权；原始 source 与所有模型/native 计数审计。新参考不得通过松这些限值获得速度。

必须重新定义并验证：三足准静态 READY、每腿前身体停走、固定四腿顺序、单个 30/40 mm 目标及一次 1500 controls 上限。两腿支撑时三角形静态裕度不再适用，不能把一个无法满足的旧门静默删掉后称“原安全门全通过”。新接触表、最少承载轮数、允许的摆动组合、失接触处理、实际接触反力与无腾空规则须在可行性合同中明确。原 dynamic_margin 只是 COM 减去参考加速度项的代理，不是真实 CoP 或稳定性定理；新阶段须用真实 native 状态、接触和载荷支撑有限工况的安全结论，不宣称形式化全局安全。

## 固定控制与 RL 的分工

先用同一身体／足端同步参考、动作边界、接触规则和限幅器实现有速度反馈及触地反馈的强固定控制器。它应根据目标速度生成步幅和周期，根据当前速度误差调整落点，并按真实接触决定相位推进；不能故意选慢固定周期给 RL 留胜算。开发数据确定并冻结这一合理最强固定对照，以及新条件的持出集合。

RL 的候选权限是每个实际接触相位中的推进速度和落点／身体参考残差，由当前速度误差、姿态角速度、实际承载、脚相进度与可达余量决定；它不能选择 physics step、删除接触门或提升扭矩限值。不沿用仅每个旧宏一次的 ±4 mm XY 残差作为唯一动作。采用连续速度跟踪、停止和净位移目标；价值估计必须含可辨识脚相／接触状态，按完整 episode 切分检查真实 return 的数值拟合，不能只因为换成更大网络就假定 C32 问题已解决。这里不冻结训练超参或预算。

同任务比较须预先冻结命令阶梯及通过条件。每个算法的“最高合格速度”只取双向、停止／反向、误差、native 安全、保持和成本全部通过的最高共同命令档。RL 提速证据需在新的持出条件下超过同权限强固定对照，例如最高合格速度至少高 20%，同时达到最低工程速度；确切阈值在后续合同冻结。若两者都已跟踪同一速度上限，不能靠超调声称 RL 更快；稳定性或误差收益可以单独报告，但不冒充提速。

## 下一步的有界顺序

发布 C34 已闭合的“速度变快但质量失败”。随后只做新调度器的最小确定性参考／接口和固定可行性，不启动训练；验证必须能回答“两相接触权限能否安全支持数倍速度”，而不是再完成一轮小幅参数扫描。可行后才冻结同权限强 fixed、held-out 条件与真实 RL 预算。不可行则记录哪项真实 native 或执行器约束阻断，回到动作权限设计。GUI 的持键、松键、反向、失焦与 TTL 语义最后接入已合格控制器，不把纸面速度或 headless 单场结果当成用户体验交付。
