# 联合外推压力测试

零残差与三份随机化策略共 16 个案例全部失败，结束于 0.92–3.16 s，非平坦地形曝光均为零。
这次没有观察到可用的外推鲁棒性。失败前的短轨迹 RMSE 不用来排名。

## 固定条件

[协议](protocol.json)在第一例运行前写入，指定所有案例、模型与输入文件 SHA-256。
只加载九模型延迟研究中 h4_dr 的三个预算末端 checkpoint，训练 seed 为 27000/28000/29000，
每个 32768 样本；没有依据压力测试成绩选模型或重训。

- 30 ms 整包测量延迟，即三个 10 ms 控制拍；fusion 状态源、四帧 328 维观测。
- gyro、加速度计、编码器位置/速度的每样本噪声标准差分别变为 0.004 rad/s、
  0.06 m/s²、0.001 rad、0.01 rad/s。它们是训练设置的两倍，方差为四倍，bias 不变。
- 接触滑动摩擦系数乘 0.6，扭转与滚动摩擦不变；不追加电机被动摩擦。
- 执行器当拍理想响应，仍保留原 16 轴力矩限值；没有加入执行器延迟。
- 两张既有开发道路，每张回合 seed 为 17/29，真正测量 seed 由 reset 派生并写在各
  `*_episode.json` 中。所有策略与零残差使用相同命令、道路及测量随机序列。

低层控制均为轮速 PI `0.55/1.5`、偏航反馈 `4`、腿 PD 比例 `1`、姿态 PD 比例 `0.25`。
此处零残差也用四帧包装，但动作始终为零。

## 复查与重做

[独立算术检查](arithmetic_audit.json)复用已有的 CSV/NPZ 检查函数，另外核对这项特殊协议的
配置与配对关系。它没有重新仿真，不把原记录的机械活动量当成电池功率。
父目录的 `source.json/source.tar.gz` 包含实际压力适配脚本；子目录协议明确指向父源码记录，
不能直接当作普通主线 `audit_evaluation` 输入。

```bash
python scripts/evaluate_d1_unseen_stress.py \
  --study results/d1_v3_delay_ablation --output results/my_joint_stress
```

先加 `--preflight-only` 可在不创建输出的情况下检查并加载全部三个可信模型。
正式运行要求新的输出目录；已有失败不被覆盖。重跑器还要求当前生产源码与训练快照一致，
将来修改控制链后应先恢复对应源码到隔离目录。
原始 CSV/NPZ 和源码归档见[下载说明](../../docs/reproducibility.md)。

30 ms 超出训练的 0–20 ms 延迟范围，噪声与摩擦也同时改变。这只是一个组合压力点，
没有覆盖多种组合，不能单独归因为“摩擦太小”或“随机化无效”，也不是新的地形留出。
下一项诊断应固定另两个因素，只扫描其中一个；当前数据不支持直接迁移到真机。
