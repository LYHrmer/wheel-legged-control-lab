# 单帧、短历史与随机化：九模型延迟对照

固定预算下，四帧历史和本次随机化训练都没有带来稳定的延迟容忍能力。
20 ms 时单帧 h1 完成 2/12 例，四帧 h4 为 0/12，h4_dr 为 1/12；30 ms 时三组均为 0/12。
无延迟时三组各 12/12 完成并达到质量门槛。

## 先固定协议，再运行

[预声明协议](protocol.json)保存了全部 39 次命令：9 次训练、27 次策略评测、3 次公共零残差评测。
三个训练 seed 为 27000/28000/29000，每模型 32768 个样本，共 294912 样本。
均取预算末端 checkpoint，不按开发结果加预算、换 seed 或挑模型。

三组的含义、历史拼接及复跑单个模型的命令见[学习文档](../../docs/delay_learning_lab.md)：

- h1：单帧 82 维，训练无测量延迟、执行器理想。
- h4：四帧 328 维，其余训练条件同 h1。
- h4_dr：四帧；每回合随机采样 0–20 ms 测量延迟、0–6 ms 执行器纯延迟、
  0–6 ms 执行器时间常数、0.95–1.05 执行器增益。

控制周期 10 ms，物理周期 2 ms。低层配置固定为轮速 PI `0.55/1.5`、偏航反馈 `4`、
腿部 PD 比例 `1`、姿态 PD 比例 `0.25`。所有评测使用 fusion 与理想执行器；
每次评测为两张开发道路 × 回合 seed 17/29，每例上限 60 s。
实际测量 seed 由 reset 派生，分析器核对配对值相同。

这批道路参与过低层参数诊断，不是新地形留出。不能将其与
[六模型 oracle 留出成绩](../d1_v3_locomotion_report/README.md)混在一张收益表中。

## 独立复查

[分析器](../../scripts/analyze_d1_delay_ablation.py)已复查 39 次运行的源码一致性、
9 个模型的预算与 sidecar、108 个策略案例和 12 个公共零残差案例。
它复用 CSV/NPZ 算术检查，拒绝缺模型、缺案例或配置不同的输入。
完整时长指标只对 60 s 案例计算；h1→h4、h4→h4_dr 配对任一失败则连续指标差为 `null`。
不能用不同幸存子集的平均 RMSE 做整体优劣判断。

```bash
python scripts/analyze_d1_delay_ablation.py \
  restored-artifacts/results/d1_v3_delay_ablation \
  --output results/my_delay_analysis.json
```

九模型的 [576 次 PPO 更新](ppo_math_audit.json)也通过了独立数值复算。
检查的是 GAE 与保存的概率运算，不是优化器重放，更不代表策略具备鲁棒性。
原始 CSV/NPZ、更新片段和源码压缩包按[下载说明](../../docs/reproducibility.md)获取。

旧评测协议保存的是外部模型路径，没有逐评测模型副本。当前 checkpoint/sidecar 哈希一致
与路径匹配不能独立证明当时加载的模型字节；源码归档哈希也不是来源认证。

## 这组结果能回答到哪里

本次预算和控制配置下，增加历史没有解决 20/30 ms 问题；随机化仅出现一次 20 ms 完成，
没有形成跨训练 seed 的稳定收益。h1 与 h4 的第一层网络参数量不同，h4_dr 又同时改变了
测量和执行器随机化，不能进一步作单因素归因。

30 ms 超出训练的测量延迟范围。追加的[组合压力测试](../d1_v3_unseen_stress/README.md)
同时改变噪声与滑动摩擦，16 例全部失败，也不支持 sim-to-real 结论。
下一步先分离测量与执行器随机化，并检查低层反馈在各固定延迟下的闭环行为；
只提高训练预算还不能区分这些原因。
