# D1 小起伏与缓坡训练

本页保留第一版环境与实验定义。后续的倒滑诊断和控制参考修改见
[第二版地形跟踪](terrain_tracking_v2.md)，两个版本的模型不能混用。

这项实验把 PPO 的训练地面从平地扩展到小起伏和缓坡。机器人沿世界 x 方向行驶，
经典控制使用原有 LQR＋VMC，策略补充两维合力残差。键盘课程、跳跃和旧 42 维策略保持原样；
本实验有单独的环境和 checkpoint，不能直接装进旧演示入口。

先读[学习指南](learning_guide.md)里的残差控制与 PPO，再用本页检查环境定义。
训练是否带来收益，要看同一地形上的配对误差，不能只看回合是否跑完。
[已运行的三种子结果](../results/d1_terrain_curriculum/README.md)包含原始轨迹和负结果，
没有显示课程训练相对平地训练的明确优势。

## 从一个高度错误开始

设机身世界高度为 z，当前位置地面高度为 h(x,y)。本实验跟踪的 clearance 为

```text
c = z - h(x,y)
e_c = c - c_target                 c_target = 0.455 m
z_target(t) = h(x_t,y_t) + c_target
```

假设机器人在 4° 上坡上，以 0.45 m/s 行驶 2 s，水平位移是 0.9 m。地面升高
`0.9 × tan(4°) = 0.0629 m`。如果高度目标仍固定在世界 z=0.455 m，clearance 就会少
约 63 mm。这个误差已经超过高度奖励的 30 mm 尺度两倍。

所以观察、奖励和跌倒判断都使用相对地面高度。观察第 10 项是 `e_c / 0.08`；
`0.08 m` 仅为归一化尺度，目标高度仍为 `0.455 m`。奖励高度项沿用
`exp(-(e_c/0.03)**2)`。相对高度小于 `0.22 m` 会终止回合；机身 Roll 或 Pitch 超过
`0.85 rad`、状态非有限数或驶出地图安全内区也会终止。

控制目标读取步前地面，奖励读取步后地面。例如上坡行驶了一步后，不能拿上一位置的 h
计算当前 clearance。对应测试是
[`test_transition_reward_and_next_observation_have_explicit_height_timing`](../tests/test_d1_terrain_env.py)。
它人为加入已知位移，检查控制目标与奖励目标确实使用不同位置。

机身姿态命令的 Roll/Pitch 仍为世界坐标的 0，旧 LQR 线性化工作点保持不变。
本实验没有把机身目标改成平行于坡面，也没有新增坡度重力前馈。

## 地形怎样进入物理仿真

[`training_terrain.py`](../src/wheel_legged_control/d1/training_terrain.py)创建有限高度场：
x 范围 ±6 m，y 范围 ±3 m，x 每 1 cm 一个采样点，y 两行使用相同数据。
三种剖面是平地、`A sin(2πx/λ+φ)` 和 `x tan(θ)`。A 表示振幅，峰谷差为 2A。

碰撞使用 MuJoCo 高度场，oracle 查询读取同一份 float32 数据并做单元线性插值。
测试用 `mj_ray` 对照真实碰撞面，包括负坡高度和法向符号。上坡沿 +x 升高时，
按 D1 的世界 RPY 定义，参考 Pitch 为负值。这里的角度不能直接当成任意偏航下的机身纵向坡角。

高度场在编译后按固定高度范围写入，避免每次把 5 mm 和 10 mm 地形各自归一化成同样的峰谷差。
MuJoCo 的高度场存储和编译规则见[官方 hfield 说明](https://mujoco.readthedocs.io/en/stable/XMLreference.html#asset-hfield)。
每次 reset 原位换数据，不重新编译模型。复用已创建的 Renderer 时还需上传新的高度场，
否则画面可能仍显示旧地形；物理碰撞更新不依赖这一渲染操作。

reset 后会检查地面穿透。坡面在机身中心处高度为 0，不表示前后轮也处在高度为 0 的地面上。
若初始姿态相交，就按接触距离补高并留 2 mm 余量，写入 `initial_height_lift_m`。
这个过程只更新几何状态，不悄悄运行一段物理仿真；回合时间从 0 开始。

## 固定四阶段课程

采样函数在
[`terrain_env.py`](../src/wheel_legged_control/d1/terrain_env.py)的 `sample_training_terrain()`。
它只接收随机数生成器和阶段编号，不接收评测成绩。

| 阶段 | 平地 | 起伏 | 缓坡 |
|---|---:|---|---|
| 0 | 100% | 无 | 无 |
| 1 | 50% | 50%，A=5 mm | 无 |
| 2 | 30% | 35%，A均匀采样5–10 mm | 35%，±2° |
| 3 | 25% | 25%，A均匀采样5–10 mm | 50%，±2°或±4° |

训练波长从 `0.8 / 1.0 / 1.2 m` 中采样，相位随机。训练速度为 `0.20–0.45 m/s`，
只前进、不转向。每局先站立 0.3 s，再用 0.3 s smoothstep 提升速度；这些时间计入训练预算。
正式对照默认关闭域随机化、动作延迟和观测噪声，也没有旧平地训练中的随机大推力。

阶段按总环境转移步数的四等份推进，只对下一次 reset 生效。一局内不能换地形，
否则轮地接触会突然跳变。向量环境可能在阶段边界继续跑完旧回合，因此实际各阶段步数
不会恰好相等。需要检查 `metadata.json` 的 exposure 统计及 `episode_starts.json` 中的
真实采样参数；进入第 3 阶段也不保证短训练已经抽到每一种坡度。

这里借鉴了 `legged_gym` 将地形类型和难度分别组织的做法，具体见其
[`Terrain.curiculum()` 源码](https://github.com/leggedrobotics/legged_gym/blob/master/legged_gym/utils/terrain.py)。
本项目采用自己的固定步数调度，未移植其训练系统。性能自适应晋级可以留作另一组实验，
目前固定日程便于比较相同训练预算，也避免引入一套未经检验的晋级阈值。

## 策略能读什么、能改什么

新观察为 44 维：前 42 维沿用旧字段布局，其中高度误差已换成 clearance 误差，末尾添加
地面 Pitch/Roll。schema 为 `d1-terrain-oracle-v1`。机身状态和地形参考都直接来自仿真，
这里没有实现 IMU/编码器融合或真实地形感知。

动作仍是两维 `[-1,1]` 残差，分别缩放为 `±11.25 N` 纵向合力和 `±20 N` 竖直合力，
schema 为 `d1-terrain-residual-quarter-v1`。原有控制器随后合成并限制关节力矩。
新尺度只作用于新环境；旧环境仍是 `±45/80 N`。图中的残差 N 表示送入控制器的合力请求，
不等于独立测得的轮地接触力。

这个评测入口没有键盘演示的策略门控。日志分别记录路径是否启用、是否被门控，以及动作值。
“启用”不意味着动作非零，也不意味着动作已经改善了跟踪。

速度误差使用机身 x 方向速度，前进距离使用世界 x 位移。这个直行实验中两者方向接近，
但若机器人发生明显偏航，它们就不能互相替代；日志另存了偏航角。

## 跑一次对照

先在仓库根目录安装项目依赖；训练还需要可选的 `.[rl]`。以下命令使用 CPU。
每次指定新的输出目录，脚本拒绝覆盖已有结果。

```bash
# 先检查开发地形上的零残差控制，不需要Torch
python scripts/run_d1_terrain_curriculum.py --mode baseline \
  --evaluation-split development --episode-seconds 4 \
  --output results/my_terrain_baseline

# 验证完整训练、保存重载与评测流程；默认评测开发集
python scripts/run_d1_terrain_curriculum.py --steps 8192 --envs 4 \
  --seeds 0 1 2 --episode-seconds 4 \
  --output results/my_terrain_development
```

两类 PPO 都重新初始化，网络 `[64,64]`、学习率 `3e-4`，每个环境 rollout 长度 128，
batch 128，每轮更新 4 epoch。物理周期为 2 ms，策略和控制周期为 10 ms。
`gamma=exp(-0.01/2)=0.99501248` 对应 2 s 折扣时间常数，GAE λ=0.95。
总预算向上取整到完整 rollout，实际步数写入协议。最后一次 PPO 更新的训练指标也会落盘。

绘图入口读取日志，不需要加载策略：

```bash
python scripts/visualize_d1_terrain_curriculum.py \
  --run results/my_terrain_development --output results/my_terrain_development/figures
```

它会从 CSV 重算 RMSE、检查 case 配对完整性，并画出每个训练 seed 的差值。
`--render-scenes` 可另外渲染固定地形的零残差重放，需要可用的 MuJoCo OpenGL 后端，
例如在命令前设置 `MUJOCO_GL=egl`。这些场景图不会加载训练策略，不能用作策略通过地形的证据。

评测三组分别为零残差、仅平地训练的 PPO、课程训练的 PPO。零残差每个 case 只跑一次；
两类 PPO 各训练 3 个种子，保存 final checkpoint 后重新加载，用确定性动作完成同一组 case。
没有按留出成绩挑 checkpoint。三组共享新的地面相对高度控制目标。

留出集使用波长 `0.7 / 0.9 / 1.1 m` 和 ±3° 坡；平地 case 则检查已训练地形上的保留能力。
±3° 位于训练坡度范围内，只是未训练过的参数值，不能称为大范围分布外泛化。
开发代码和预算确定后，再用 `--evaluation-split holdout` 运行预先冻结的实验。
若看过该轮留出成绩后继续改参数，应把这批 case 视作开发资料，另设下一轮留出集。

输出包含 `protocol.json`、源码/依赖记录、训练指标 CSV、模型及其 SHA、逐步评测 CSV，
以及文件校验清单。`metrics.csv` 中的 completed 只表示到达时间上限且未触发终止，
不表示跟踪成功。速度 RMSE、高度 RMSE、前进距离和力矩饱和比例应一起读。
SB3 原始训练 CSV 中的 `rollout/success_rate` 沿用环境 `is_success`，同样只表示存活到时间上限，
不能将该字段画成地形通过率。
前进比例的分母是逐步速度命令的积分，包含起步过程，不能简单拿目标速度乘总时长。

比较时先在每个训练 seed 内计算相对零残差的配对差，再观察三个 seed 的差异。
不要把一局的 400 个控制步当成 400 次独立实验。若策略提前终止，RMSE 只覆盖已执行的轨迹，
必须连同终止原因和持续时间报告，避免短暂存活的策略反而显得误差更低。

这个对照能检查多地形课程相对只训平地是否有帮助。它没有“从头随机混合全部地形”的第四组，
所以无法单独证明分阶段调度优于普通多地形训练。短预算也不能证明策略收敛。

## 动手检查

1. 在 ±4° 开发坡道上只跑零残差，从逐步 CSV 画 clearance 误差随位置的曲线。
   用前面的 `tan(4°) × Δx` 计算绝对高度目标可能引入的漂移，再看当前误差是否仍有趋势。
   目标定义正确也可能跟踪不好；不要把两件事混在一起。
2. 改 `sample_training_terrain()` 中一个阶段的混合比例，保留预算与随机种子，另开开发结果目录。
   先查看实际抽到了多少种地形，再解释训练曲线。若没有抽到目标坡度，这次实验不能回答该坡度的收益。
3. 将新环境两维残差尺度各减半，重新训练两组。比较速度误差和残差请求，同时检查关节饱和。
   小动作可能减轻扰动，也可能失去补偿能力；关节是否更容易饱和需要测量，不能预设方向。

想继续推进到更真实的控制问题，可以先补一组全阶段随机地形对照，或在开发集检验坡度重力前馈。
随后再研究非 oracle 地形参考和接触参数误差。当前剖面只有纵向变化，尚未覆盖横坡、碎石、
台阶攀爬和跳跃；它也没有验证真机可迁移性。
