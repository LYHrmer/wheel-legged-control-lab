# B22 46：跟踪奖励形状——对数平方误差（设计）

状态：**COMPLETE（未过门，但为目前最好结果）**：镜像合池0.8834、逐对6/6、成本1.026，rough_0p35改善12.2%；见[实际结果](b22_logsse46_results_20261018.md)。本修订基于对现有轮腿奖励的完整审阅，提出并训练一个只改**跟踪项形状**的候选。它是单臂、单变量对照：与 44 的 `ffyaw` 同起点、同课程、同预算、同前馈基线，只差奖励。

## 一、现有奖励（冻结的九项）

`full_drive_env_08.py::_reward` 给出九项，`world_upright_course_11.py` 只把姿态项换成 world roll/pitch：

| 项 | 公式 | 量级 |
|---|---|---|
| tracking_vx | `2·exp(−(e_vx/0.25)²)` | 0…2 |
| tracking_vy | `exp(−(e_vy/0.12)²)` | 0…1 |
| tracking_yaw | `exp(−(e_yaw/0.4)²)` | 0…1 |
| height | `−0.2·(e_h/0.08)²` | ≤0 |
| attitude | `−0.2·((r/0.2)²+(p/0.2)²)` | ≤0 |
| actual_torque | `−0.02·mean((τ/τ_lim)²)` | ≤0 |
| action_change | `−0.01·mean(Δa²)` | ≤0 |
| leg_speed | `−0.005·mean((q̇/20)²)` | ≤0 |
| termination | `−10`（终止时） | 0 / −10 |

评测指标则是**无加权的归一化平方误差和** `J = Σ[(e_vx/0.25)² + (e_yaw/0.4)²]`（drive 窗口）。奖励与评测用了同一个分母，但**形状不同**：奖励对误差做指数，评测对误差做平方。

## 二、为什么现有形状不够（已有证据）

1. **小误差处 exp 被压平。** `exp(−q) ≈ 1 − q + q²/2`，在 q 很小时对 q 的斜率是 −1（对总奖励上限 4 而言），而评测关心的正是 q 的小值区。42 的 α=8 变换只是把斜率放大到 −8，形状仍是 exp。
2. **42 的实际收益只有 3.11%**（deficit8 对 zero 的合池 SSE）。同一份[信号分析](b22_reward_signal_analysis_20261018.md)显示平地上 tracking 两项在 91.9%/94.2% 的 drive 拍已位于上限 1% 以内——平地信号接近饱和，而 rough 的方差最大（逐拍总奖励 std 0.117），却仍未被压下去。
3. **45 的负结果**：把粗糙地面样本从 9.2% 提到 29.8%，rough_0p35 反而从 19.75 变差到 20.65，其它任务全面退步。**继续加样本不解决问题**，说明瓶颈是“奖励没有表达出粗糙地面误差的重要性”，而不是“没见够”。
4. **诊断**：flat_1p2_yaw 的偏航 SSE 约 95% 是闭环增益缺口，而 rough 的剩余误差同时包含速度（13.4）与偏航（6.7）。评测对二者同权重，奖励对 vx 的权重是 2:1 且都被 exp 压平。

## 三、候选：对数平方误差项（不新增第 10 项）

冻结的训练 reader 把奖励项集合硬编码为九项（`read_training22.REWARD_NAMES` 与 `numeric.reward_terms9` 的九列），新增项会破坏已完成运行的验证接口。因此本候选**只改变已有两项的形状**：

```
tracking_vx  = 2 + α(2e^(−qx) − 2) − β·ln(1 + min(qx, cap))
tracking_yaw = 1 + α(e^(−qy) − 1) − β·ln(1 + min(qy, cap))
qx = ((vx − cmd_vx)/0.25)²,  qy = ((wz − cmd_wz)/0.4)²
```

参数：**α=8（与 44 的 `ffyaw` 相同）、β=8、cap=4**。β=0 时逐位等于 44 的奖励。

为什么是这个形状：

- **小误差区线性于评测 SSE。** `ln(1+q) ≈ q`，所以新项在每个 drive 拍上直接惩罚评测所用的量，形状与 J 一致。q=0 时新项为 0，完美跟踪时两项上限仍为 2 和 1，不改变“更好就更高”的排序。
- **大误差区对数压缩。** 线性惩罚 q 会让一个 0.5 m/s 的误差在奖励里占到整回合量级；`ln(1+q)` 在 q=4 时只有 ln5≈1.61，乘 β=8 为 12.9，与终止惩罚 −10 同量级，不会让极端误差主导训练。
- **cap=4 的目的**：把单拍额外惩罚封顶在 12.9；超过该误差通常已伴随终止或安全条件。
- **β=8 的依据**：用已完成运行的现实误差估计。rough_0p35 的 zero 速度 RMSE≈0.042 m/s（qx≈0.028）、偏航 RMSE≈0.048 rad/s（qy≈0.014）。在该点，α=8 的 exp 项梯度约 −16e^−q≈−15.6（每单位 q）；新项梯度为 −β/(1+q)≈−7.8，使总跟踪梯度从约 −15.6 提升到约 −23.4（**+50%**）。β=2 只有 +12%，不足以对抗 42 只 3.11% 的增益；β=16 会到 +100%，接近翻倍，风险偏大。β=8 是两者之间、以现有误差幅值算出的中值。

## 四、为什么不是其它方案

| 备选 | 为什么不选 |
|---|---|
| 缩小 exp 的尺度（0.25→0.12） | 等价于改变所有误差的敏感度，但大误差处 exp 迅速归零，梯度再次消失；且与 42 的 α 对照不可比 |
| 直接 `−β·q`（线性平方） | 极端误差会主导奖励（q=25 时 −200），训练不稳定 |
| 新增第 10 项 `tracking_sse` | 冻结 reader 的九项接口与 `reward_terms9` 九列不允许；改接口会破坏已完成运行的复核 |
| 提高训练样本中 rough 的比例 | 45 已实测为负结果 |
| 改动作空间/控制权限 | 影响面更大，且不是奖励设计问题；留作后续独立候选 |

## 五、实验与判定

- 单臂 `ffsse`：完整 B22 + Adam 起步，FF=3.9 前馈基线，α=8、β=8，课程与 44 `ffyaw` 逐位相同（`yaw_emphasis`），32768 拍。
- 预算：32768 controls / 163840 normal-native / 2 compiler-native；4 GiB 有效可用内存持续 10 秒启动、运行保留 2 GiB、整组 2/3 GiB、无 swap、单线程串行、不重试不续跑。
- 训练是否有效由独立 reader 判定（九项逐拍独立复算，包括新形状与保存的归一化误差）。
- 训练完成后导出 NumPy actor，在 FF=3.9 基线上跑原六任务，用 43 同一独立 reader 与 `score_pairs` 贡献门（合池 SSE 比 ≤ 0.85、逐对 ≤1.02 至少 4 对、成本比 ≤1.20），与 44 `ffyaw`（0.9024、6/6、1.111）对照。
- 门不放宽；单次训练、单种子；若未过门，如实记录并说明下一步。

## 六、风险

- 新项在 drive 段与停车段都计入。停车段命令为零、轮子刹停，速度误差小，额外惩罚接近 0；但若策略在停车末段出现速度扰动，新项会放大该扰动。评测的停车门与原奖励一致，须在结果中检查。
- `ln` 在 q 很小时斜率有限但非零，理论上会让策略在“已经很好”的平地上继续追求微小改善，可能牺牲力矩成本。成本门（≤1.20）会暴露这一点。
- 训练只覆盖 32768 拍；与 44 相同的样本量，比较的是奖励形状而不是数据量。
