# B22 45：前馈基线上的粗糙地面强化训练（单臂）

状态：**PREPARING**。[44 的结果](b22_yawtrain44_results_20261018.md)里没有任何组合越过 RL 贡献门（合池比 ≤ 0.85）：最好的是旧权重加镜像（0.8976）与转向课程臂 raw（0.9024）；转向任务现在只剩 2.8 的 SSE，而 rough_0p35（19.4，占合池 52%）和 ramp（8.2）才是剩余缺口。本修订只问一个问题：**在 `ffyaw` 的基础上提高粗糙地面训练占比，能否降低 rough_0p35 的误差而不伤其它任务。**

## 训练臂（单一变量：粗糙地面样本占比）

`ffrough` 与 44 的 `ffyaw` 完全同条件：同一完整 B22 与同一 Adam 状态出发、FF=3.9 前馈基线、deficit-8 奖励、32768 拍。课程是 `ffyaw` 的转向课程表把两个 slot 移到粗糙地面：

| slot | `ffyaw` | `ffrough` |
|---|---|---|
| 0 | 平地，低速 (0.4–0.9)，带转向 | **粗糙地面**，低速 (0.25–0.4)，带转向 |
| 6 | 平地，1.6 m/s，直行 | **粗糙地面**，低速 (0.25–0.4)，直行 |
| 其余（1、2、3、4、5、7）及前 8 个热身回合 | — | 与 `ffyaw` 逐位相同 |

粗糙地面回合占源日程的比例由 1/8 升到 3/8，转向 slot 数保持 4，评测的 rough_0p35（速度 0.35）落在训练速度区间内。`ffrough` 失去了“平地 1.6 m/s 直行”这一个 slot；评测里对应的 flat_1p6 只占合池很小的份额，若它回退会在结果里如实出现。

## 与 44 的差异

沿用 44（及 42）的 bootstrap / 训练 / 独立 reader 机制与全部冻结来源固定，不改任何已完成运行所依赖的文件；差异只有：臂定义和课程在 `scripts/b22_roughtrain45.py`，阶段只有 bootstrap 和一个训练臂，首批数据配对改为对照 44 已通过读回的 `ffyaw` 配对证明（同一初始状态与首个回合）。预算：32768 controls / 163840 normal-native / 2 compiler-native，资源规则同 42：4 GiB 有效可用内存持续 10 秒启动、运行保留 2 GiB、任务组 2 GiB high / 3 GiB max / 无 swap，单线程串行，不重试、不续跑。

## 判定

训练只回答是否有效且通过独立 reader。科学结论来自随后的评测：导出 NumPy actor（raw 与镜像平均），在 FF=3.9 基线上跑原六任务，用 43 同一独立 reader 与 `score_pairs` 贡献门，并与 44 的各臂对照。门不放宽。
