# B22 48：2× 预算的决定性实验（设计）

状态：**PREPARING**。依据[开源对照与诊断](b22_open_source_review_20261020.md)与[优化后的方案](b22_plan48_20261020.md)：我们只有 32 次 PPO 更新、32768 samples，而官方 D1 是 4096 环境 × 6500–20000 迭代。本修订只回答一个问题——**把预算翻倍，是否让 seed 摆动变小、均值变好**。奖励保持 44 的 `ffyaw`（β=0）不变。

## 一、设计

| 项 | 值 |
|---|---|
| 臂 | `ffyaw_b2_s31`、`ffyaw_b2_s41`（β=0，α=8） |
| seed | 201031、201041（`seed` 与 `ppo_seed`） |
| 预算 | 每臂 **65536 controls / 64 rollouts**（2×），n_steps 1024、batch 256、最多 4 epochs |
| 课程 | `yaw_emphasis`，与 44/47 逐位相同；66 个源回合，仍在封存的 0..79 内 |
| 基线 | 1× 的两个 seed：0.9324 / 0.8586（镜像，47 结果） |
| 资源 | 4 GiB 持续 10 秒启动、运行保留 2 GiB、整组 2/3 GiB、无 swap、Nice10 单线程串行、不重试 |

## 二、实现：两处计数式派生

冻结协议把 32768/32 写死在两个模块里，直接改会失去来源可追溯。本修订用**精确计数替换**派生内存副本，替换次数不符即失败：

- `learning21.py`：10 处（`BudgetSpec(65536,1024,256,4)`、num_timesteps/transitions、train_calls/rollouts=64、epochs/optimizer 上界、metadata 计数、clip 审计条数）。
- `read_training22.py`：9 处（`N=65536`、rollouts/train_calls=64、predict_values 的 64+truncated、前后向计数、numeric/gaussian blocks=64）。
- 另在 worker 与 reader 的 spec 副本中覆盖 `controls_per_arm_per_stage=65536`、`rollouts_per_arm_per_stage=64`、`total_controls_max=65536`。
- 磁盘上的冻结文件与它们的 SHA 不变；派生证明写入读取回执。

## 三、预注册判定（跑之前写死）

主结果用镜像合池比（raw 为次），与 1× 的 seed 201011/201021 对比：

| 2× 的结果 | 结论 | 下一步 |
|---|---|---|
| 两 seed 均值比 1× 改善 **> 0.01**，且极差不变差 | **预算确认是杠杆** | 此后固定 2×、n≥3；再考虑扩展课程规格到 4× |
| 改善 ≤ 0.01，或极差变大 | 本地微调范式到极限 | 停止本地奖励调参，转结果收束与论文写作 |

不允许挑选较好的 seed；两个 seed 与两臂都完整报告。

## 四、成本与风险

- 训练+读回约 35 分钟/臂，导出 3 分钟，评测 14 分钟 → 两臂约 2 小时。
- 2× 后每臂归档约 1.6 GiB，两臂约 3.2 GiB；任务组内单阶段配额 5 GiB、整轮 12 GiB。
- 主要风险：派生遗漏某个硬编码常量导致读回失败。失败会在模型加载或读回处显式报错，消耗为 0 或很低；旧目录保留、不覆盖。

## 五、本修订不做的事

- 不改奖励形状（方向已关闭）、不改控制器、不改门、不换默认策略。
- 不扩展到 4×/8×；那需要新课程规格，作为 P2 的独立决定。
