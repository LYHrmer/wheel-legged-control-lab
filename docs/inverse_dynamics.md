# D1 任务空间逆动力学 QP

这个分支把机身运动任务直接变成 16 路关节力矩。它是独立的平地原型，通过
`D1InverseDynamicsController.compute(command, state)` 调用。原来的 VMC、LQR/MPC 和
PPO 路径保持不变，键盘演示也仍使用旧控制器。

先验证站立和直线前进制动，再施加一次水平推力。这里没有接触规划，也没有新的 RL 策略。
非零转向命令会被拒绝，不能用这一版声称已实现轮足全地形运动。

## 跑一次开发回放

在仓库根目录安装项目后运行：

```bash
python -m pip install -e '.[dev]'
python scripts/evaluate_d1_inverse_dynamics.py --output /tmp/d1-idqp-dev
python -m pytest tests/test_d1_inverse_dynamics.py
```

输出目录中已有结果时，脚本拒绝覆盖。`steps.csv.gz` 保存每个控制步的状态、预测加速度、
16 路输出力矩和逐轮接触力；`summary.json` 保存运行版本、场景设置和压缩 CSV 的 SHA256。
`gzip -dc /tmp/d1-idqp-dev/steps.csv.gz | head` 可以查看列名。

默认场景使用开发种子 21–23。种子只改变初始 roll/pitch，范围是 ±0.01 rad；质量和摩擦
都不随机化。每回合 6 秒，仿真步长 2 ms，控制周期 10 ms。

| 场景 | 指令与扰动 |
|---|---|
| stand | 速度指令始终为 0 |
| drive_brake | 第 1–3 秒速度指令为 0.5 m/s，其余时间为 0 |
| push | 第 2–2.12 秒在机身施加世界系 +x 方向 120 N 推力 |

这里的“完成”只表示回合没有跌倒或拒绝求解。需要同时看速度误差、制动后的末速和姿态。
这些开发种子参与过排错，不能改称留出测试，也不能和旧的随机域审计直接比较。

## 从任务到力矩

决策变量为

$$
z=[\ddot q_{22},\ f_{12},\ \tau_{16}]^T.
$$

前 6 个速度自由度属于浮动基座，其余 16 个对应关节。每个车轮有一个三维接触力，方向
约定为地面对机器人的力，统一使用世界坐标系。控制器同时求解这 50 个变量：

$$
M(q)\ddot q+h(q,\dot q)=S\tau+\sum_iJ_i(q)^Tf_i.
$$

`S` 是 22×16 的力矩选择矩阵；模型的电机 gear 都为 1。`M` 包含关节 armature；
`h = qfrc_bias - qfrc_passive` 包含重力、速度相关项和名义黏性阻尼。关节干摩擦及关节
限位反力不在这条名义方程中。MuJoCo 将它们作为约束处理，不能把全部
`qfrc_constraint` 填进 `h`，否则会把仿真器求出的接触力也带进控制器。
参见 [MuJoCo 动力学与约束说明](https://mujoco.readthedocs.io/en/stable/computation/index.html)。

机身速度、高度和姿态通过 PD 变成加速度目标。腿关节围绕名义姿态；车轮跟踪
`forward_velocity / wheel_radius`，不跟踪累计旋转角度。

| 加速度任务 | PD 增益 | 代价权重 |
|---|---|---|
| 机身平面速度 | 速度增益 3/s | x、y 各 1 |
| 基座高度 | 80/s²、18/s | 5 |
| 机身姿态 | 80/s²、16/s | roll/pitch 各 10，yaw 阻尼 2 |
| 12 个腿关节 | 30/s²、6/s | 每关节 0.05 |
| 4 个轮转速 | 10/s | 每轮 0.05 |
| 接地点侧向速度 | 20/s | 每轮 1 |

机身姿态误差用旋转向量表示，目标姿态保留当前 yaw，因而没有绝对航向保持。
加速度残差分别按 1 m/s²、1 rad/s² 作为参考尺度，权重是任务偏好。还有很小的加速度、
接触力和力矩正则项。加权最小二乘组成 OSQP 的 `P` 和 `q`，采用
`0.5 zᵀPz + qᵀz` 约定；见 [OSQP Python 接口](https://osqp.org/docs/interfaces/python.html)。

硬约束包括完整浮基动力学、关节力矩上限，以及每个活跃接触的

$$
0\le f_n\le0.65mg,\qquad |f_t|+|f_l|\le0.55f_n.
$$

这个摩擦菱形位于圆锥内，是保守近似；0.55 是控制器假设，不读取仿真地面摩擦。
非接触轮的三维力严格为零。滚动、法向速度稳定对应的加速度等式是硬约束，侧向只加惩罚。
接触标志来自状态快照，不会为了让 QP 可行而把悬空轮当作支撑点。

## 为什么滚轮的导数要单独算

对轮心 `c`、单位轮轴 `a`、地面法向 `n` 和半径 `r=0.087 m`，采用薄圆轮近似：

$$
u=n-a(a^Tn),\qquad \rho=-r\frac{u}{\|u\|},\qquad p=c+\rho.
$$

接触瞬间的材料点速度是 `v_c=J(q) qdot`。但下一瞬间轮缘上接触地面的材料点已经变了。
直接把 `mj_jacDot(p)` 当作滚动点的导数，会留下不该有的材料点向心加速度。
纯轮转速 10 rad/s 的独立探针中，这一项为 8.7 m/s²；修正后约为零。

实现使用

$$
b=\dot J_{\rm material}\dot q+
\omega\times(\dot\rho-\omega\times\rho).
$$

法向在一个控制步内保持不变，`rho_dot` 由上面的投影归一化式求导。
`mj_jacDot` 的调用条件见
[MuJoCo API](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html#mj-jacdot)。

局部坐标的三行依次为滚动方向 `t=normalize(a×n)`、侧向 `l=n×t` 和法向 `n`，记为 `F`。
控制器对局部速度施加 20/s 的稳定项：

$$
FJ\ddot q+Fb+\dot Fv_c=-20Fv_c.
$$

其中第 1、3 行为等式约束，第 2 行是软任务。`F_dot` 也必须求导，实际 yaw 角速度可以
非零，即使转向指令为零。测试用 `mj_integratePos` 向前、向后微移配置，对整个
`F(q)J(q)` 做中央差分，不复用控制器的解析导数。

## 状态和模型的分界

控制器内部持有独立名义模型，只从 `D1StateEstimate` 重建配置和速度。它不接收正在运行
的 plant，也不使用快照中的旧 3×4 腿部 Jacobian 或实测接触力。完整 Jacobian 是 3×22。

现有快照有一个需要保留兼容性的约定：`base_position` 位于 `base_link` 原点，但
`base_linear_velocity_*` 来自 MuJoCo 的机身惯性质心速度。新模型转换为

$$
v_{\rm origin}=v_{\rm COM}-\omega_{\rm world}\times(Rr_{\rm COM}).
$$

旧控制器的数值行为没有改动。回放 CSV 的 `origin_velocity` 明确使用原点速度。
单看腾空动力学残差无法发现这一错误，因为给整个自由系统加上统一平移速度不改变这里的
瞬时动力学；带角速度的滚动差分检查才会把它暴露出来。

当前状态源仍是仿真真值。独立名义模型避免了偷读随机域参数，但不等于已经有传感器估计器。

## 求解成功之后还检查什么

`last_result` 保存不可变快照，`reset()` 清空它。无效命令抛出 `ValueError`；不可接受的
QP 解抛出 `RuntimeError`。每次计算前先清空旧结果，回放脚本遇到拒绝就停止该回合。
这一版没有故障回退控制器，回放不会继续施加上一次成功力矩。

OSQP 的 `solved` 或 `solved inaccurate` 只是候选状态。代码先把浮点容差导致的微小
力矩越界裁剪回执行器限值，再对同一个候选重算全部约束，逐行违反量超过 `1e-4` 则拒绝。
输出力矩与 `last_result.command_torque_nm` 一致，避免仿真器二次裁剪后诊断仍记旧值。

`dynamics_residual_max` 和 `constraint_violation_max` 是数值检查标量，各行采用原生单位：
动力学平移行是 N，转动及关节行是 Nm，接触加速度行是 m/s²。它们不是具有统一单位的
物理误差范数。合力预测与仿真差异单独用 N 报告：先将四轮力求和，再与五个物理子步的
实测均值比较。逐轮数值保存在 CSV；合力误差小不代表每个车轮的误差都小。

还有一条独立测试：把预测 `qacc` 交给另一份关闭接触求解和干摩擦的 MuJoCo 模型，用
`mj_inverse` 与 `mj_applyFT` 检查力矩和接触力是否闭合。这个测试不读取控制器的 `M/h/J`。
软接触实际轨迹不需要和理想无滑动预测逐项相同，不能把两类检查混在一起。

## 一次有用的失败

最早的站立版只有腿姿态任务，没有轮转速任务。完全对称初态能站住，但种子 21、22 的
轻微倾斜会留下部分悬空轮。QP 利用这些轮子的加速反作用调节机身，轮速升到约 118 rad/s，
机身也开始自行加速，最终达到求解迭代上限。

补上四轮转速软任务后，原先的失败回归通过，同样的开发场景也能跑完。
所以“没有跌倒”和“控制正确”要分开看。以后改任务权重时，至少同时检查悬空轮转速和制动末速。

可以从两个小实验开始：降低轮速任务权重，看轻微倾斜初态何时开始变差；再改变名义摩擦
假设，记录摩擦约束触发与速度误差。每次只改一项，使用新的输出目录。不要拿旧留出种子调参。

薄轮近似忽略了实际圆柱碰撞体的宽度与接触力矩。名义模型还没有干摩擦、关节限位反力，
也没有外力观测器；真实碰到关节限位后不能用小 QP 残差证明物理一致性。
求解器每步重新建问题，没有稀疏结构缓存；`compute_wall_p99_ms` 只描述这台电脑的测量，
不代表 100 Hz 硬实时保证。转向、台阶和跳跃仍留在下一阶段。
