# D1 任务空间逆动力学 QP

这个分支把机身运动任务直接变成 16 路关节力矩。它是独立的低速控制原型，通过
`D1InverseDynamicsController.compute(command, state)` 调用。原来的 VMC、LQR/MPC 和
PPO 路径保持不变，键盘演示也仍使用旧控制器。

默认每步冷求解，`warm_start=True` 单独启用热启动。支持低速差速转向，缓坡回放也使用
同一个控制接口。这里没有接触规划，没有新的 RL 策略，不能声称已经实现轮足全地形运动。

## 跑一次开发回放

在仓库根目录安装项目后运行：

```bash
python -m pip install -e '.[dev]'
python scripts/evaluate_d1_inverse_dynamics.py --output /tmp/d1-idqp-dev
python -m pytest tests/test_d1_inverse_dynamics.py
```

输出目录中已有结果时，脚本拒绝覆盖。`steps.csv.gz` 保存每个控制步的状态、预测加速度、
16 路输出力矩和逐轮接触力；`summary.json` 保存运行版本、场景设置和压缩 CSV 的 SHA256。
`gzip -dc /tmp/d1-idqp-dev/steps.csv.gz | head` 可以查看列名。

默认场景使用开发种子 21–23。种子只改变初始 roll/pitch，范围是 ±0.01 rad；质量和摩擦
都不随机化。每回合 6 秒，仿真步长 2 ms，控制周期 10 ms。

| 场景 | 指令与扰动 |
|---|---|
| stand | 速度指令始终为 0 |
| drive_brake | 第 1–3 秒速度指令为 0.5 m/s，其余时间为 0 |
| push | 第 2–2.12 秒在机身施加世界系 +x 方向 120 N 推力 |

“完成”只表示回合没有跌倒或拒绝求解；`validation_passed` 还检查姿态和速度等指标。
完整平地协议为三种场景 × 种子 21–23 × 6 秒。不完整协议或指标不通过时，脚本保存结果后
返回非零退出码。制动末一秒使用水平速度模长 RMS，避免前向速度很小却仍在侧滑。
这些开发种子参与过排错，不能改称留出测试，也不能和旧的随机域审计直接比较。
固定代码版本的 [9 回合结果](../results/d1_inverse_dynamics/README.md) 已保存，含逐步数据。
新增的[热启动结果](../results/d1_inverse_dynamics_warm/README.md)分别保存耗时对照与实际
控制轨迹，包含平地、转向和坡道的 24 个开发回合。默认冷求解仍保留数值对照门槛。

## 从任务到力矩

决策变量为

$$
z=[\ddot q_{22},\ f_{12},\ \tau_{16}]^T.
$$

前 6 个速度自由度属于浮动基座，其余 16 个对应关节。每个车轮有一个三维接触力，方向
约定为地面对机器人的力，统一使用世界坐标系。控制器同时求解这 50 个变量：

$$
M(q)\ddot q+h(q,\dot q)=S\tau+\sum_iJ_i(q)^Tf_i.
$$

`S` 是 22×16 的力矩选择矩阵；模型的电机 gear 都为 1。`M` 包含关节 armature；
`h = qfrc_bias - qfrc_passive` 包含重力、速度相关项和名义黏性阻尼。关节干摩擦及关节
限位反力不在这条名义方程中。MuJoCo 将它们作为约束处理，不能把全部
`qfrc_constraint` 填进 `h`，否则会把仿真器求出的接触力也带进控制器。
参见 [MuJoCo 动力学与约束说明](https://mujoco.readthedocs.io/en/stable/computation/index.html)。

机身速度、高度和姿态通过反馈变成加速度目标。腿关节围绕名义姿态；第 i 个车轮跟踪
`(forward_velocity - yaw_rate * lateral_offset_i) / wheel_radius`，不跟踪累计旋转角度。
轮心侧向偏置由独立名义模型计算，并变换到当前航向坐标系。左转时右轮目标转速更高。

| 加速度任务 | PD 增益 | 代价权重 |
|---|---|---|
| 机身平面速度 | 速度增益 3/s | x、y 各 1 |
| 基座高度 | 80/s²、18/s | 5 |
| 机身姿态 | 80/s²、16/s | roll/pitch 各 10，yaw 为 2 |
| 转向速率积分修正 | 40/s²，积分限幅 ±0.1 rad | 并入 yaw 加速度目标 |
| 12 个腿关节 | 30/s²、6/s | 每关节 0.05 |
| 4 个轮转速 | 10/s | 每轮 0.05 |
| 接地点侧向速度 | 20/s | 每轮 1 |

机身姿态误差用旋转向量表示，目标姿态保留当前 yaw，因而没有绝对航向保持。
转向积分在收到非零转向命令后工作，制动时继续修正；接触轮少于两个、时间倒退或间隔
超过两个控制周期时清空，`reset()` 也清空。纯直线命令不会启用积分。这是带限幅的误差
反馈，没有估计或读取外部扰动力矩。
加速度残差分别按 1 m/s²、1 rad/s² 作为参考尺度，权重是任务偏好。还有很小的加速度、
接触力和力矩正则项。加权最小二乘组成 OSQP 的 `P` 和 `q`，采用
`0.5 zᵀPz + qᵀz` 约定；见 [OSQP Python 接口](https://osqp.org/docs/interfaces/python.html)。

硬约束包括完整浮基动力学、关节力矩上限，以及每个活跃接触的

$$
0\le f_n\le0.65mg,\qquad |f_t|+|f_l|\le0.55f_n.
$$

这个摩擦菱形位于圆锥内，是保守近似；0.55 是控制器假设，不读取仿真地面摩擦。
非接触轮的三维力严格为零。滚动、法向速度稳定对应的加速度等式是硬约束，侧向只加惩罚。
接触标志来自状态快照，不会为了让 QP 可行而把悬空轮当作支撑点。

## 为什么滚轮的导数要单独算

对轮心 `c`、单位轮轴 `a`、地面法向 `n` 和半径 `r=0.087 m`，采用薄圆轮近似：

$$
u=n-a(a^Tn),\qquad \rho=-r\frac{u}{\|u\|},\qquad p=c+\rho.
$$

接触瞬间的材料点速度是 `v_c=J(q) qdot`。但下一瞬间轮缘上接触地面的材料点已经变了。
直接把 `mj_jacDot(p)` 当作滚动点的导数，会留下不该有的材料点向心加速度。
纯轮转速 10 rad/s 的独立探针中，这一项为 8.7 m/s²；修正后约为零。

实现使用

$$
b=\dot J_{\rm material}\dot q+
\omega\times(\dot\rho-\omega\times\rho).
$$

法向在一个控制步内保持不变，`rho_dot` 由上面的投影归一化式求导。
`mj_jacDot` 的调用条件见
[MuJoCo API](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html#mj-jacdot)。

局部坐标的三行依次为滚动方向 `t=normalize(a×n)`、侧向 `l=n×t` 和法向 `n`，记为 `F`。
控制器对局部速度施加 20/s 的稳定项：

$$
FJ\ddot q+Fb+\dot Fv_c=-20Fv_c.
$$

其中第 1、3 行为等式约束，第 2 行是软任务。`F_dot` 也必须求导，实际 yaw 角速度可以
非零，即使转向指令为零。测试用 `mj_integratePos` 向前、向后微移配置，对整个
`F(q)J(q)` 做中央差分，不复用控制器的解析导数。

## 状态和模型的分界

控制器内部持有独立名义模型，只从 `D1StateEstimate` 重建配置和速度。它不接收正在运行
的 plant，也不使用快照中的旧 3×4 腿部 Jacobian 或实测接触力。完整 Jacobian 是 3×22。

现有快照有一个需要保留兼容性的约定：`base_position` 位于 `base_link` 原点，但
`base_linear_velocity_*` 来自 MuJoCo 的机身惯性质心速度。新模型转换为

$$
v_{\rm origin}=v_{\rm COM}-\omega_{\rm world}\times(Rr_{\rm COM}).
$$

旧控制器的数值行为没有改动。回放 CSV 的 `origin_velocity` 明确使用原点速度。
单看腾空动力学残差无法发现这一错误，因为给整个自由系统加上统一平移速度不改变这里的
瞬时动力学；带角速度的滚动差分检查才会把它暴露出来。

当前状态源仍是仿真真值。独立名义模型避免了偷读随机域参数，但不等于已经有传感器估计器。

## 求解成功之后还检查什么

`last_result` 保存不可变快照，`reset()` 清空它。无效命令抛出 `ValueError`；不可接受的
QP 解抛出 `RuntimeError`。每次计算前先清空旧结果，回放脚本遇到拒绝就停止该回合。
这一版没有故障回退控制器，回放不会继续施加上一次成功力矩。

OSQP 的 `solved` 或 `solved inaccurate` 只是候选状态。代码先把浮点容差导致的微小
力矩越界裁剪回执行器限值，再对同一个候选重算全部约束，逐行违反量超过 `1e-4` 则拒绝。
输出力矩与 `last_result.command_torque_nm` 一致，避免仿真器二次裁剪后诊断仍记旧值。

`dynamics_residual_max` 和 `constraint_violation_max` 是数值检查标量，各行采用原生单位：
动力学平移行是 N，转动及关节行是 Nm，接触加速度行是 m/s²。它们不是具有统一单位的
物理误差范数。合力预测与仿真差异单独用 N 报告：先将四轮力求和，再与五个物理子步的
实测均值比较。逐轮数值保存在 CSV；合力误差小不代表每个车轮的误差都小。

还有一条独立测试：把预测 `qacc` 交给另一份关闭接触求解和干摩擦的 MuJoCo 模型，用
`mj_inverse` 与 `mj_applyFT` 检查力矩和接触力是否闭合。这个测试不读取控制器的 `M/h/J`。
软接触实际轨迹不需要和理想无滑动预测逐项相同，不能把两类检查混在一起。

## 一次有用的失败

最早的站立版只有腿姿态任务，没有轮转速任务。完全对称初态能站住，但种子 21、22 的
轻微倾斜会留下部分悬空轮。QP 利用这些轮子的加速反作用调节机身，轮速升到约 118 rad/s，
机身也开始自行加速，最终达到求解迭代上限。

补上四轮转速软任务后，原先的失败回归通过，同样的开发场景也能跑完。
所以“没有跌倒”和“控制正确”要分开看。以后改任务权重时，至少同时检查悬空轮转速和制动末速。

可以从两个小实验开始：降低轮速任务权重，看轻微倾斜初态何时开始变差；再改变名义摩擦
假设，记录摩擦约束触发与速度误差。每次只改一项，使用新的输出目录。不要拿旧留出种子调参。

薄轮近似忽略了实际圆柱碰撞体的宽度与接触力矩。名义模型还没有干摩擦、关节限位反力，
也没有外力观测器；真实碰到关节限位后不能用小 QP 残差证明物理一致性。
`compute_wall_p99_ms` 只描述这台电脑的测量，不代表 100 Hz 硬实时保证。
台阶和跳跃尚未经过这套控制器的验收，旧键盘演示的能力也不能算作它的结果。

## 求解耗时：先检查输出有没有变

冷启动配置不跨控制步传递求解器状态。固定权重和执行器约束在构造时准备；质量矩阵
用一次 `mj_fullM` 展开，三维叉积改用 `mju_cross`。任务代价按对角块和姿态的 3×3 块
组装，省去大部分零元素运算。动力学方程、任务权重及求解容差保持不变。

同输入对照入口：

```bash
python scripts/benchmark_d1_inverse_dynamics.py --output /tmp/d1-idqp-latency.json
```

脚本从本地可信提交 `6faf813` 加载旧控制器，采集种子 22 的 600 步前进制动轨迹。
两版控制器复用这些状态，交替先后顺序测三遍，每版得到 1800 个耗时样本。它们来自
同一个场景的重复回放，不能当作 1800 个独立实验。构造与首次调用耗时单独记录，随后
10 次预热只记录方法，不保存耗时。
除 P50/P95/P99 外，JSON 还报告 P99.9 和最坏单步耗时，原始尾部样本不会丢弃。
模型和依赖使用当前工作树，只冻结参考控制器文件；运行时会执行该文件，不能传入不可信提交。

测量前设定的目标是中位耗时下降至少 25%、P99 下降至少 15%。还要没有拒绝解，
逐项力矩差不超过 0.001 Nm、接触力差不超过 0.05 N、广义加速度差不超过 0.01
（各自由度原生单位）。任一项未通过，脚本写完报告后返回非零退出码。
这些是冷启动配置的本机开发目标，没有加入 CI，也不构成硬实时证明。

曾试过缓存整个 QP 并热启动。一次同输入诊断中，中位耗时从 4.09 ms 降到 1.35 ms，
但最大力矩差达到 12.99 Nm，逐轮接触力差达到 28.76 N；广义加速度差只有约 `4.1e-5`。
因此没有将热启动当作等价替换。接触力的正则系数约为 `4.5e-10`，身体加速度相近时，内部力分配
仍可能对求解初值敏感。仅清空上一轮的原始变量和对偶变量也不够，还需考虑自适应 rho
留下的状态。本机 OSQP 1.1.3 默认按迭代次数调整 rho，不能把这种差异归因为运行时间噪声。

现在把热启动保留为独立数值配置。它仍报告上述差异，但 `performance_passed` 与
`numerical_equivalence_passed` 分开保存；性能通过后，还必须单独通过平地闭环协议。

```bash
python scripts/benchmark_d1_inverse_dynamics.py --warm-start --output /tmp/d1-idqp-warm-time.json
python scripts/evaluate_d1_inverse_dynamics.py --warm-start --output /tmp/d1-idqp-warm-rollout
python scripts/plot_d1_inverse_dynamics.py --latency /tmp/d1-idqp-warm-time.json \
  --rollout /tmp/d1-idqp-warm-rollout --output /tmp/d1-idqp-warm.png
```

缓存还有一个容易漏掉的细节：按当步非零元素生成 CSC 结构，600 次调用中仍会重建
514 次。改成按方程块预留结构项后，同一轨迹只重建 3 次，其余更新数值。加速度代价块
预留完整上三角，力和力矩只预留对角；动力学与接触约束按对应块预留。数值变成零时不删
结构项。接触组合或力矩限幅变化时重建，拒绝求解与 `reset()` 会清掉历史。

## 转向和坡道实验

```bash
python scripts/evaluate_d1_inverse_dynamics_mobility.py --output /tmp/d1-idqp-mobility
```

| 场景 | 时间 | 命令与通过条件 |
|---|---|---|
| turn_left / turn_right | 各 6 s | 第 1–4 秒为 0.3 m/s、±0.2 rad/s；带符号转角 0.4–0.8 rad，随后停稳 |
| ramp_stand | 6 s | 在 8° 坡中起步，保持支撑面上方高度 |
| ramp_to_deck | 12 s | 从坡中以 0.25 m/s 驶上平台并制动 |
| ramp_from_flat | 20 s | 从坡前平地起步，进入坡道后到平台制动 |

默认均使用开发种子 21–23，初始 roll/pitch 扰动仍为 ±0.01 rad。坡中初始化只用场景
几何设置初始姿态，三个种子均有四轮初始接触；这不意味着全程四轮贴地。平地进入坡道时
使用已知平地 `z=0` 作为初始先验，观测到有效接触面后不再回退到该先验。

坡前起点单独设在 `(2.86, 0, 0.455) m`。最初复用了课程的 `x=2.75` 起点，三个回合
在 0.38–1.17 秒内因接触法向超过 15° 停止，尚未抵达坡底。重建失败帧发现后轮接触的是
碎石区末列凸块，其边缘位于 `x=2.545 m`。新位置由轮碰撞体与地形的静态间距确定，
回归测试检查后轮离开凸块、前轮心仍在坡底之前；没有移动凸块、修改坡道或放宽法向门槛。
旧键盘课程起点保留，避免把这次实验修正混入已有演示。

目标生成器从状态中的接触点拟合 `z=a*x+b*y+c`，至少需要三个接触点且 XY 拟合秩为 2。
支撑面系数用 0.12 增益滤波，接触不足时保持上次估计并记录年龄。控制目标不读取场景
标签或平台高度。`D1Command.base_height_m` 仍是世界 z，新增的
`base_vertical_velocity_mps` 默认为零，明确提供高度变化率：

```text
z_ref  = a*x_base + b*y_base + c + 0.455
vz_ref = forward_velocity * (a*cos(yaw) + b*sin(yaw))
az_ref = 80*(z_ref-z) + 18*(vz_ref-vz)
```

姿态目标按同一支撑面的前后、左右坡度生成。直接把身体 pitch 命令当作坡度会混淆两种
语义；对高度阶跃直接求导又会产生尖峰，所以这里单独传递速度前馈。旧 VMC 路径拒绝
非零竖直速度前馈，原有命令保持原行为。车轮接触法向允许偏离竖直方向最多 15°，实际
地形验收只覆盖 8° 坡道，不能把参数上限当作已验证的爬坡能力。

平台验收要求最后完整一秒内四个轮体都与平台接触，平均接触点位于平台内部，且水平速度
RMS 小于 0.03 m/s；还需至少两秒停车观察。平台几何仅用于这个独立检查，不能反馈给控制
目标。坡道姿态误差峰值须小于 5°，支撑面净空误差峰值须小于 4 cm。支撑面估计无效时，
净空指标使用保持的估计，CSV 单独记录有效性，不能把它解释成已知的真实地形净空。
这些检查采样于 100 Hz 控制周期端点，不保证中间五个物理子步都满足。

初版转向只有约 ±0.195 rad，未达到预先设定的转角范围。日志中，稳态 QP 仍预测约
1.7 rad/s² 的竖直轴角加速度，实际却接近零，轮力矩没有饱和。薄轮接触模型漏掉的侧向
擦滑阻力留下了持续偏差。加入限幅积分并保留制动阶段的积分历史后，左右转向回归通过。
转向角速度指标使用世界角速度的 z 分量，低姿态角时接近欧拉 yaw 的导数；两者没有混称。

移动回放额外保存每步输入、输出 `qpos/qvel`，可从记录离线渲染，不重新执行控制器：

```bash
MUJOCO_GL=egl python scripts/render_d1_inverse_dynamics_mobility.py \
```
