# 闭环控制与 PPO：几道能手算的检查题

配合[单轮闭环](wheel_control_lab.md)和[一次 PPO 更新](ppo_update_lab.md)使用。下面的
数字是手构造题目，不是仿真运行记录。先遮住答案，用纸笔算一次，再回到代码检查。

## 1. 积分冻结了，为什么输出却没有饱和

仍用 kp=0.12、ki=0.6、dt=0.002 s、限矩 ±2 Nm。某一时刻之前，积分状态已经累积到
0.498 Nm，这不是 reset 后的第一步。现有两个连续控制采样，误差分别是 +5 和 +1 rad/s，
参考模型已经算出的前馈力矩分别为 0.9 和 0.85 Nm。

计算每一步的 P、积分增量、候选积分、候选总力矩、最终积分、请求力矩和命令力矩。
再判断 `integration_frozen` 和 `saturated`。

### 核对答案

| 量 | 第一步 | 第二步 |
| --- | ---: | ---: |
| P，Nm | 0.6 | 0.12 |
| 积分增量，Nm | 0.006 | 0.0012 |
| 候选积分，Nm | 0.504 | 0.4992 |
| 候选总力矩，Nm | 2.004 | 1.4692 |
| 最终积分，Nm | 0.498 | 0.4992 |
| 请求力矩，Nm | 1.998 | 1.4692 |
| 命令力矩，Nm | 1.998 | 1.4692 |
| `integration_frozen` | true | false |
| `saturated` | false | false |

第一步候选总力矩超上限，积分增量仍为正，因此拒绝这次增量。用原积分重新计算后，
请求力矩只有 1.998 Nm，不再超限。第二步应沿用被保留的 0.498，而不是被拒绝的 0.504。

这些答案只能确定 `command_torque_nm`。若执行器有两步延迟，
`applied_torque_nm` 来自两步前的命令，还需要延迟队列历史才能算。没有这段历史，不能把
当前命令直接称为实际施加力矩。

## 2. 模型前馈承担了多少力矩

打开同一对象、同一参考下 `nominal_ff` 和 `identified_ff` 两条 CSV。使用完全相同的
时间窗，读取：

```text
time_s, reference_velocity_rad_s, actual_velocity_rad_s
proportional_torque_nm, integral_torque_nm, feedforward_torque_nm
requested_torque_nm, command_torque_nm
```

分别计算该窗口的速度 RMSE、平均绝对积分力矩与平均绝对前馈力矩。再找一次换向，画出
P、I、FF 的有符号曲线，核对它们相加等于请求力矩。

如果跟踪误差降低且积分负担也减小，这支持“模型项承担了原先需要反馈纠正的部分力矩”
这一解释；积分没有减小，也不能据此否认前馈的作用。动态跟踪中各项有相位和符号，
平均值会丢失信息。需要区分惯量、黏性和摩擦项时，从 `fit.json` 和参考速度/加速度
分别重算，或者做单项关闭实验。

先按参考速度选定同一换向窗口，再套用到两组数据。不要分别挑每组误差最小的区段，
也不要按各自实际速度选不同时间样本后直接比较。

## 3. 限幅和延迟能从同一列看出来吗

打开 `stress_nominal_ff.csv` 与 `stress_identified_ff.csv`，分别算：

$$
\Delta\tau_{limit,k}=\tau_{requested,k}-\tau_{command,k},\qquad
\Delta\tau_{delay,k}=\tau_{command,k}-\tau_{applied,k}.
$$

第一项对应控制器限幅截去的力矩；第二项在本台架中来自命令延迟。即使没有限幅，只要
命令随时间改变，第二项也可能不为零。恒定命令处于限幅上限时，延迟队列追上当前值后，
第二项反而可以为零。

在相同时间轴上画两项残差、跟踪误差与积分状态，再检查冻结标志。由此可以观察误差峰
附近有哪些限制，但单看相关性仍不能确定主要原因。若要分离原因，另做“只改变力矩上限”
和“只改变真实执行器延迟”的对照；保留同一组模型前馈参数，不要顺手重新辨识。

## 4. 一次 PPO 的五个参数如何变化

这个纸笔例子比默认脚本少一维观测。给定 s=1，actor 的均值为 μ=w·s+b，初始 w=0.5、
b=0、log_std=0。critic 为 V=w_v·s+b_v，初始 w_v=1、b_v=0。

冻结动作 a=0.9、优势 A=2、return target R=3，以及采样时旧 log probability。当前网络
尚未更新，因此 ratio=1。取 clip_range=0.2、vf_coef=0.5、ent_coef=0.01、学习率 0.1。
没有优势归一化、梯度裁剪、动量或权重衰减。

$$
L=-\min(rA,\operatorname{clip}(r,0.8,1.2)A)
+0.5(V-R)^2-0.01H.
$$

求 loss、五个参数的梯度和一次 SGD 后的值。注意：旧概率是常量；不能把分子和分母都
写成同一个带梯度的当前概率，否则会把 ratio 恒等成 1，错误地消掉策略梯度。

### 核对答案

初始高斯熵 H=0.5·ln(2πe)≈1.418939，因此 L≈−0.0141894。
初始 ∂logπ/∂μ=0.4，∂logπ/∂log_std=0.4²−1=−0.84。

| 参数 | 梯度 | 更新后：旧值 − 0.1×梯度 |
| --- | ---: | ---: |
| w | −0.8 | 0.58 |
| b | −0.8 | 0.08 |
| log_std | 1.67 | −0.167 |
| w_v | −2 | 1.2 |
| b_v | −2 | 0.2 |

log_std 的梯度包含熵项：−2×(−0.84)−0.01=1.67。更新后的 μ=0.66、V=1.4，
同一个冻结动作的概率比约为 1.230，已经越过 1.2。这一步说明 clip 不是对参数或概率比
执行硬投影；后续若继续优化这条正优势样本，需重新判断目标函数采用哪一支。

这里算的只是一个冻结样本的更新。默认脚本有 8 个样本、7 个参数，梯度还需对样本取平均。
返回[更新实验](ppo_update_lab.md)，从 `parameters.csv` 任取一行验证同一个 SGD 等式，
再从 `samples.csv` 检查相应概率比；loss 下降不能替代新策略的独立回报评测。
