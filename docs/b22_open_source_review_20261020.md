# B22 开源四足 RL 对照与诊断（2026-10-20）

**目的**：用同机器人（DDTRobot D1）和主流四足 RL 开源实现，核对我们的奖励设计与训练规模，判断 42–47 的负结果到底卡在哪。

## 一、对照对象（均为可访问的开源仓库）

| 仓库 | 与我们的关系 | 训练规模 |
|---|---|---|
| [legged_gym](https://github.com/leggedrobotics/legged_gym)（ETH） | 四足 RL 的基线框架 | 4096 envs × 24 steps × 1500 iters ≈ **1.47×10⁸** samples |
| [ddt_rl_isaacgym](https://github.com/DDTRobot/ddt_rl_isaacgym)（官方 D1） | **同一台 D1** 的 Isaac Gym 训练 | `configs/d1/d1_rough_config.py`：4096 × 24 × 6500 ≈ **6.39×10⁸** |
| [DDT_Lab](https://github.com/DDTRobot/DDT_Lab)（官方 D1，Isaac Lab/NP3O） | **同一台 D1** 的新版训练 | D1 rough `max_iterations=20000`：4096 × 24 × 20000 ≈ **1.97×10⁹** |
| [Wheel-Legged-Gym](https://github.com/clearlab-sustech/Wheel-Legged-Gym) | 轮足机器人，legged_gym 派生，VMC 动作 | 框架同上，规模同量级 |
| [Swiss-Mile / ANYmal on wheels](https://arxiv.org/abs/2405.01792) | 轮足四足的分层 RL | 同量级训练 + 实机 |

我们的单臂预算是 **32768 controls**。相对上表：
- 比 legged_gym 默认少 **约 4500 倍**；
- 比官方 D1 的 Isaac Gym 配置少 **约 19500 倍**；
- 比官方 D1 的 Isaac Lab/NP3O 配置少 **约 60000 倍**。

PPO 更新次数：我们 32 次（32768/1024），官方 D1 是 6500–20000 次迭代。

## 二、奖励设计对照

| 项 | 我们（B22） | legged_gym | 官方 D1（Isaac Lab） |
|---|---|---|---|
| vx 跟踪 | `2·exp(−(e/0.25)²)` | `exp(−e²/0.25)`，权重 1.0 | `2·exp(−e²/0.25)` |
| yaw 跟踪 | `exp(−(e/0.4)²)` | `exp(−e²/0.25)`，权重 0.5 | `1·exp(−e²/0.25)` |
| 小误差二次系数（每 m²/s²） | **32.0** | 4.0 | 8.0 |
| 总奖励裁剪 | 无 | `only_positive_rewards=True`（终止项在裁剪后加） | 同左 |
| 姿态 | `−0.2·((r/0.2)²+(p/0.2)²)` | `−0·‖g_xy‖²` | `−1.0·‖g_xy‖²` |
| 高度 | `−0.2·(e/0.08)²` | `0`（目标 1.0 m 时不启用） | `−1.0·(h−0.49)²` |
| 力矩/动作率 | `−0.02·mean(τ/τ_lim)²`、`−0.01·mean(Δa²)` | 力矩 `−1e−5`、动作率 `−0.01` | 力矩 0、功率 `−2e−5`、动作率 `−0.01`、平滑 `−0.002` |
| 其他 | 无 | 足端滞空、碰撞、软限位 | 足端镜像、相位接触、过度滞空、COM-足接触等 |
| 跟踪项门控 | 无 | 无 | **乘以直立系数** `clamp(−g_z,0,0.7)/0.7` |
| 域随机化 | （本修订未启用/未对照） | 摩擦 0.5–1.25、推力、噪声 | 摩擦 0.2–1.25、质量 ±、COM ±0.05、电机 0.9–1.1、KP/KD ±10%、3 拍延迟、±30 N 扰动 |
| 课程 | 每回合脚本化地形/速度/转向 | 距离驱动地形课程 + 速度课程 | 同左 |

**关键发现 1：我们的跟踪核函数不是"太平"，而是比开源更尖。** 在小误差处，我们的二次系数是 32，legged_gym 是 4，官方 D1（Isaac Lab）是 8。46 的设计假设是"exp 在小误差处被压平"，这个假设相对于开源基线不成立——我们本来就比它们敏锐 4–8 倍。这解释了 46 的奖励形状改动为什么没有可测收益。

**关键发现 2：差距在样本量/更新次数，不在奖励项。** 32 次 PPO 更新、单环境、每次更新 1024 步；开源是 4096 个并行环境、6500–20000 次迭代。

## 三、我们自己数据里的证据

用已保存的控制记录与权重核对（只读，无新训练/物理）：

| 指标 | 实测 | 含义 |
|---|---|---|
| 探索噪声 `log_std` | ≈ 0.139（腿与轮一致），父代与四个终代几乎不变 | 训练几乎没改变探索幅度 |
| 策略均值残差 RMS | 0.054–0.090（各任务） | 均值幅度只有噪声的 **0.39–0.53 倍** |
| 残差动作占满量程 | 4–9% | 动作远未用满 |
| 动作饱和拍数 | **0/全部驱动拍** | 控制权限不是瓶颈 |
| 同配置换 seed 的镜像结果 | 0.9324 → 0.8586（**7.4 点**） | 单次训练的结果由噪声采样主导 |

**结论**：在 32 次更新下，策略均值还没有明显超过探索噪声；最终权重更接近"初值 + 若干随机方向"，而不是"奖励函数塑造出的解"。因此臂间 1–2 点的差异无法与 seed 噪声（最大 7.4 点）区分。这与 47 的预注册判定一致。

## 四、因此修正的两个旧判断

1. **"奖励形状太平"不成立**：我们的核函数比开源更尖，46 的改法方向本身就不对。
2. **"粗糙地形需要更大控制权限"证据不足**：残差只用了 4–9% 的量程、零饱和；45 的负结果也不支持"样本不够"。

## 五、必须说清的边界

开源方案依赖 GPU 与 4096 并行环境，本机（无 GPU、任务组 3 GiB）**无法复现同量级训练**。本仓库应被定位为**小样本微调研究**（在已有基控制器上做 32k 步残差微调），其结论不能外推到"端到端四足 RL"。任何"追上开源"的表述都不成立。
