# 侧步单次提交

课程入口现在默认使用 `commit_cycle_v1`：停稳后短按 A 或 D，请求一次完整侧步；长按则逐步重复。
松键不会取消当前已经开始的一步。当前快步周期实测约 10.6 秒，输入方式没有让步态变快。

```bash
python scripts/run_d1_course_drive.py --zone start --seconds 60 \
  --output results/my_committed_side_step_01
```

先按 `1` 回平地起点并停稳，再短按 A 或 D。最初约一秒仍在移动支撑重心，身体可能暂时
向相反方向移动；应观察完整周期。中途按反向键只改变下一周期的意图，完成边界仍按着它才会换向。
活动中的短按不会排队，松键后最多继续当前周期。

`X` 请求安全取消，失焦、输入超时、跌倒或恢复状态也会取消。取消过程中继续由侧步控制器落脚，
满足原有接触与支撑条件后才交回轮式控制。之后需要真实释放 A、D 再按；A+D 同时按住不算释放。
`R` 和区域键仍是显式仿真复位，必须等新的按键采样确认释放，不能让旧输入跨段重启侧步。

侧步期间 W/S、Q/E 和高度请求保持屏蔽。Space 会被记录为阻挡，不能排队到侧步完成后突然跳跃。
已有跳跃期间输入的侧步短按也会丢弃。停稳、四轮接触和平地等实际启动门槛保持原样；
意图层提出启动请求，并不代表物理控制器已经接受。

需要对照原来的松键或反向即安全取消行为时，显式添加：

```bash
--side-input-mode release_abort
```

有限自动验证使用真实 MuJoCo 与实际课程 runner，并注入 GLFW 等价的事件和 held 采样；没有人工操作窗口。
九场矩阵累计 19,900 个控制转移，107 项检查通过；切换默认值后另做 2,000 个控制转移，确认
默认入口完成一次短按侧步且活动中的 Space 被阻挡、没有延迟跳跃。最终针对性测试为 89 项通过。

| 场景 | 实际结果 |
| --- | --- |
| A 短按 1 秒 | 10.56 秒完成，净向左 3.703 cm；交接 4 秒保留 98.30%，最大回退 0.917 mm |
| D 短按 1 秒 | 10.56 秒完成，净向右 3.704 cm；交接 4 秒保留 98.29%，最大回退 0.913 mm |
| 长按进入第二周期后松键 | 恰好完成两步，分别 3.703、3.589 cm，没有第三步 |
| A 开始后改按 D | 第一步方向保持，完成后才开始反向第二步；分别 3.703、3.564 cm |
| 支撑移动阶段与 swing 阶段按 X | 两例均保留 `cancelled`，四轮接触后交接，未把中止标成成功，按住 A 没有重启 |
| 坡道、跳跃和 R 复位 | 坡道实际 guard 拒绝启动；跳跃期间短按不迟发；复位后旧 held 不启动，新释放重按才开始 |

纯意图核心来自实际 Claude Opus，方案由 GPT-6-astra / ultra 冻结，调用原稿与本地修正分别保留。
根线程集成只修改按键意图与 runner 接缝，原直接调用 drive、两个侧步物理控制器及其参数未改。
协议和逐拍记录区分原始 held、一次性 PRESS、明确取消原因、实际传给 drive 的方向、重复计划、
释放门禁和真实控制器阶段。显式 reset 的轨迹按 segment 分开计算。
