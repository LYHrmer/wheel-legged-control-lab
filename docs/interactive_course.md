# D1 键盘驾驶与地形课程

这份笔记对应 [`interactive.py`](../src/wheel_legged_control/d1/interactive.py) 和
[`terrain.py`](../src/wheel_legged_control/d1/terrain.py)。它记录场景尺寸、控制接口、验收条件，
也保留开发中遇到的三次失败。修改控制参数后，可直接重跑文末命令核对结果。

## 从按键到 16 路力矩

键盘回调只改目标值，不直接写 `qpos` 或 `qvel`。一次 `100 Hz` 控制步按下面的顺序执行：

1. 读取速度、高度和偏航目标；
2. 读取一份不可变的 `D1StateEstimate`；
3. 用快照中的轮地接触估计局部支撑平面；
4. 更新跳跃时序、安全状态和抓地力状态；
5. LQR 或 MPC 计算纵向轮地合力，可选 PPO 输出两维残差；
6. VMC 分配四轮支撑力，用 `JᵀF` 转为腿关节力矩；
7. 加入左右轮差速偏航反馈，再执行关节力矩限幅和斜率限制；
8. MuJoCo 运行 5 个 `2 ms` 物理子步，然后生成下一份快照。

一次周期内，经典控制、PPO、地形估计和安全逻辑读取同一份快照。`oracle` source 直接采样
MuJoCo；`estimated` source 给快照加入可复现噪声和整数步延迟。

外层位置没有使用世界坐标 `x`。控制器对机身前向速度积分：

\[
s_{k+1}=s_k+v_{x,b}T_s,
\qquad
s^\star_{k+1}=s^\star_k+v^\star T_s.
\]

机器人转过 90° 后，`v_{x,b}` 仍表示它面对方向上的速度。这个定义也用于 PPO 观察、速度
奖励和 RMSE。

D1 固定轮的横向速度不可控。`A/D` 生成偏航角速度目标，低层给左右轮施加相反的差动力矩：

\[
\tau_{yaw}=k_r(\dot\psi^\star-\dot\psi),
\]

再按左负右正叠加到四个轮执行器。命令上限为 `0.6 rad/s`，差动力矩限幅 `4 Nm`。

## 支撑平面估计

估计器收集状态快照中与地形接触的轮子位置。至少三个轮子接触时，拟合平面

\[
z=a x+b y+c.
\]

世界系斜率按当前 yaw 投影到机身前向和横向，再换成 Roll/Pitch 目标。输出使用一阶滤波，
增益 `0.12`，限幅 `±0.22 rad`。控制器没有读取“当前在坡道”之类的场景标签。`oracle`
直接使用 MuJoCo 接触点；`estimated` 会扰动并延迟接触标记和位置，但仍没有实现真实接触
估计。实机上要由接触/力传感器和运动学替代。

## 跳跃时序和保护条件

空格只提出一次请求。以下条件同时满足才进入蹲伏：

- 至少三个轮子接触；
- `|roll| < 0.18 rad` 且 `|pitch| < 0.18 rad`；
- 摔倒检测未触发。

跳跃持续 `1.20 s`：

| 阶段 | 时间 | 高度目标 | 额外竖直合力 |
|---|---:|---:|---:|
| crouch | `0.25 s` | `0.405 m` | `-80 N` |
| thrust | `0.15 s` | `0.500 m` | `+450 N` |
| flight | `0.35 s` | `0.455 m` | `0 N` |
| landing | `0.45 s` | `0.435 m` | `+60 N` |

竖直前馈最终仍经过腿力矩限幅。验收程序检查 `minimum_wheel_contacts == 0`，可以排除“只把
高度目标调高、轮子仍未离地”的假跳跃。跳跃录像中基座峰值上升 `67.7 mm`，整车越过第一
根 `20 mm` 横杆。

## 安全和卡滞处理

控制状态有 `normal / degraded / recovery` 三种：

- Roll 或 Pitch 超过 `0.30 rad` 且未在跳跃时，前进命令压到 `±0.15 m/s`，偏航压到
  `±0.10 rad/s`；
- 已摔倒或基座低于 `0.28 m` 时，速度目标清零并给 `+100 N` 竖直恢复前馈；
- 16 路输出每步只能变化 `limit × dt / 0.02`，抑制按键和状态切换造成的力矩突变。

低矮方块边缘可能让轮子在平地卡住。若目标速度超过 `0.12 m/s`、实测前向速度低于
`0.08 m/s`、至少三轮接触并持续 `0.25 s`，纵向合力上限会短时从 `180 N` 放宽到 `500 N`。
检测到明显斜坡后立即取消该增益，轮电机本身仍受 `±12 Nm` 限制。

## 可选残差 PPO

启动时显式传入 checkpoint：

```bash
wheel-legged-d1-play \
  --baseline lqr \
  --policy results/d1_residual_ppo/model.zip
```

按 `L` 后，交互控制器调用与训练环境共用的 42 维观察编码器。策略动作缩放为
`[±45 N, ±80 N]`，再加到 LQR 的纵向合力和 VMC 的竖直合力上。

仓库提交的 PPO 是 `oracle` checkpoint。它的训练数据只覆盖平地参数随机化、推力、观察
噪声和 `0–30 ms` 残差动作延迟。用 `estimated` 模式重新训练时，完整反馈还会承受状态
噪声和 `0–30 ms` 状态延迟。以下状态会把动作置零：

- jump phase 不为 `ready`；
- 安全状态不为 `normal`；
- `|yaw_rate_command| > 0.20 rad/s`；
- 估计支撑面 Roll 或 Pitch 超过 `0.10 rad`。

这段门控把已评估策略的使用范围写进了代码。PPO 可以在平缓区域现场开关比较，陡坡和跳跃
仍由确定性控制器处理。

## 自动验收

```bash
wheel-legged-d1-play \
  --baseline lqr \
  --state-mode oracle \
  --audit-output results/d1_interactive
```

| 区域 | 通过 | 距离 [m] | 最大 Roll [deg] | 最大 Pitch [deg] | 四轮接触比例 | 跳跃/横杆 |
|---|---:|---:|---:|---:|---:|---:|
| start | 1 | 1.28 | 2.36 | 8.40 | 0.893 | `0 / 0` |
| rough | 1 | 2.73 | 2.82 | 8.28 | 0.660 | `0 / 0` |
| ramp | 1 | 4.91 | 0.04 | 10.50 | 0.989 | `0 / 0` |
| stairs | 1 | 3.99 | 2.72 | 7.51 | 0.706 | `0 / 0` |
| bumps | 1 | 5.13 | 2.19 | 5.09 | 0.798 | `0 / 0` |
| jump | 1 | 2.87 | 2.84 | 7.66 | 0.855 | `1 / 1` |

本机控制步 P95 为 `1.0–1.3 ms`。数值受 CPU 负载影响，验收上限设为 `10 ms`，对应
`100 Hz` 控制周期。

我也把同一套命令换成 MPC 跑了一遍。五个区域通过；台阶只前进 `1.96 m`，低于 `3.5 m`
门槛。MPC 没有摔倒，控制步 P95 为 `1.4–1.7 ms`。目前的 `20 × 10 ms` 预测域在连续台阶
上偏保守，这项没有为了表格全绿而放宽验收条件。

## 三次失败留下的改动

### 机体系速度一开始取错了

MuJoCo `mj_objectVelocity(..., local=1)` 返回 body inertial frame 的速度。D1 的 URDF 惯性
坐标与可见 `base_link` 不完全重合，早期代码却把它当作 base-link frame。转向探针暴露了
这个错误：命令沿机器人前方，控制器却积累了错误方向的距离。现在统一取得世界系速度，再用
`base_link` 的 `xmat` 显式投影；对应回归测试会构造旋转姿态检查两种结果。

### 第一版“跳障成功”只检查了离地

旧跳跃道第一根横杆高 `50 mm`。机器人能四轮离地，随后停在横杆前，验收仍返回成功。
我把条件改为基座越过横杆末端 `0.30 m`，并将入门横杆改成 `20 mm`。当前控制可以通过第一
根，`40/60 mm` 仍保留为未完成目标。

### 训练更久曾经把高度做坏

旧奖励用 `0.7 exp(-(e_h/45 mm)^2)`，对小高度偏差不敏感。400k 步候选把随机域速度 RMSE
配对差做到 `-0.008 m/s`，却把高度 RMSE 拉高 `+1.267 mm`；策略的归一化竖直动作均值约
`+0.219`，对应持续向上补偿。

当前奖励把高度项改成 `1.0 exp(-(e_h/30 mm)^2)`，竖直动作及其变化率的代价乘 2。最终
400k 模型在 30 个随机种子上的 PPO−LQR 均值差为速度 `-0.006 m/s`、Pitch `-0.073°`、
高度 `-0.221 mm`。三个置信区间仍跨 0；这次修改解决了高度漂移，还需要更多样本或更有效
的训练任务才能证明稳定收益。

## 当前还过不了的项目

- `40/60 mm` 横杆没有通过；
- 默认 MPC 参数未通过台阶的距离门槛；
- PPO 未在坡道、台阶或跳跃数据上训练；
- `oracle` 的支撑平面估计使用仿真接触真值，`estimated` 也只是人为扰动该真值；
- 恢复状态只是限速和支撑前馈，不保证从侧翻姿态自行站起；
- 没有电机模型、IMU/编码器融合或硬件通信接口。

后续实验可以从第二根横杆、扰动下转向、接触观测噪声和 curriculum terrain training 中选一项
推进。每次只改一个机制，继续覆盖当前 CSV 和 GIF；历史版本交给 Git 保存。
