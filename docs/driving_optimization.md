# D1 驾驶优化：稳定直行、越障和速度

目标是先稳定直行和停车，再可靠通过地形，最后提高实际速度。目前处于第一阶段；新航向外环改善了旧策略的方向跟踪，但完整验收还没有通过。GUI 使用经典 LQR/VMC，下面的 PPO 实验运行在另一条同步控制链，尚未接入 GUI。

## 当前证据

| 项目 | 实际结果 | 状态 |
| --- | --- | --- |
| 平地三档直行 | 目标 .30/.40/.50 m/s，稳态实际约 .311/.413/.499 m/s | 这组开发案例稳定 |
| 松键制动 | 完整重锚使平地高速档前冲 .274→.148 m，但坡上案例出现更大回退 | 保留原默认；重锚仅为显式实验模式 |
| 旧 PPO 方向 | 加入航向保持，开发道路跑满32s由1/6增加到4/6 | 有改善，完整 G1 未通过 |
| 完整侧步 | 请求后约10.56s完成约3.70cm，交接后4s保留98.3%位移 | 短按取消步态的操作问题待修 |
| 原地跳跃 | 机身上升60.86mm，四轮同时轮底净空仅5.61mm | 跳跃增强待完成 |
| 原课程越障 | 部分碎石和台阶案例卡滞，坡道有超速和停车问题 | 待第二阶段完成 |

这些数值来自实际 MuJoCo 控制步，不是动画或理想运动学。开发案例不是总体可靠性证明；相同 oracle 配置反复运行也不构成独立物理扰动。

制动的半重锚候选也未作为默认：一个从碎石出发、实际在8°坡面松键的案例，净位移仅−0.8mm，但过程先前冲8.68cm再后退8.76cm。原版峰后仅退0.91cm。净位移接近零不能证明停稳；后续制动验证同时统计前冲、回退、反向速度和持续停车。

[跳跃原始记录](../results/d1_driving_stability_development/jump_baseline/README.md)包含600个实际控制步和完整轮底几何测量。当前结果说明需要改进起跳动作；机身升高不能替代四轮离地净空。

## 跑偏来自哪里

[偏航通道实验](../results/d1_driving_stability_development/yaw_ablation/README.md)固定六个已训练模型，在同一条开发道路重新闭环推理，比较完整动作、关闭腿残差、轮残差仅保留四轮共同分量；另设公共零残差。19条回合共56,844个真实转移，全部失败保留。

去掉轮间差异后，共同时间前缀的航向误差在六个模型中都下降，五个模型的下降幅度约94%–99%。这支持轮间差分残差是多数明显偏航的直接来源。但速度只在三个模型中改善，高度多数退化；不能把去差分直接作为最终策略。

终止原因也需要读取实际状态：`fall_or_body_contact` 是合并标签。seed48002无约束策略实际因俯仰达到0.850005rad而终止，没有非轮部位触地。去差分后它的唯一失败是跑到地图的 **x 边界**，不是再次侧向漂出。

## 航向参考与真实控制

新 [航向模块](../scripts/d1_heading_reference.py)由 Claude Opus 实现，Astra ultra 制定契约。参考角度按仿真时间积分用户上一段的偏航命令；重复读取同一拍不积分，测量到的漂移不会被当成新目标。

外环输出为：

```text
航向误差 = wrap(目标航向 - 实测航向)
控制偏航速度 = clip(用户偏航速度 + 2 × 航向误差
                    - 0.4 × (实测偏航速度 - 用户偏航速度), -1, 1)
```

[闭环探针](../scripts/probe_d1_heading_hold.py)保留原82维观察、八维动作和模型权重，只将外环产生的命令送进原控制链。每个分支都根据自身当前观察重新推理；这是命令干预，不是重新训练得到的收益。原奖励跟踪的是外环控制命令，其 return 单独命名，不能与用户目标得分混用。

## 接下来怎样验收

1. **稳定直行：** 新学习任务显式提供目标航向观察和奖励；先使用已经验证的P/D外环，不同时增加积分、改动作结构和调多个学习参数。开发通过后，再用冻结的物理扰动案例检验启停、转向保持、横偏和姿态，并验证实际GUI入口。
2. **可靠越障：** 先逐级验证小台阶和原课程坡面；需要时加入主动摆腿。跳跃以同一时刻四轮最小净空、持续无接触时间和落稳判断，不再以机身升高或计时阶段结束代表成功。
3. **提高速度：** 在前两项通过的控制器上逐档增加目标，测实际速度、制动距离和越障成功率。提高速度命令本身不算提速完成。

新实验保持原正式研究的77份源码和既有结果不变。新任务将使用独立的观察、奖励和任务版本，旧模型不会通过修改sidecar伪装兼容。

## 新航向学习任务

Claude Opus 已实现 [85维环境](../scripts/d1_heading_tracking_env.py)。它继承原任务，保留82维控制观察和八维残差动作，追加目标航向误差的正弦、余弦以及用户偏航速度。新奖励增加有界的航向目标偏差项，原控制命令奖励单独保留，方便核对。

26项环境专项测试及1项独立评测测试已通过，包括真实控制轨迹与原控制链逐位对照、噪声测量与奖励真值分离、命令变化时序、终止观察，以及PPO实际更新后保存重载。代码通过不代表策略性能通过。计划固定3个种子，连续训练到65,536步，同时保留16,384步和最终模型；这一批直行训练不宣称学会任意转向。
