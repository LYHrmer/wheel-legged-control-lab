# Codex 与 Claude Opus 的项目分工

目标是提高可验证的项目收益：操作更稳定、实验结论更可靠、结果能复现和交付。按这些结果评估协作，不以调用次数或生成代码量计分。

## 当前实际收益

- Opus 主写快步控制器，本地修复数学符号、MuJoCo 接口和完成判定后，实际课程平地侧步从约 40.8 秒缩至 10.6 秒。三次连续侧步约 10.8 cm，但仍有约 1.8 cm 纵向漂移。见[实现出处、失败候选及对照](../results/d1_side_step_development/README.md)。
- 本地集成和独立验证完成 3121 项回归；真实抬腿、取消落脚和控制权交接有动力学证据。见[集成 QA](../results/d1_side_step_integration/README.md)。
- Opus 的低画质补丁从中断前的持久化会话恢复，避免重新生成。同一模型的五帧软件渲染对照，平均耗时从 0.308 秒降至 0.093 秒。[独立窗口测试](../results/d1_side_step_gui_validation/README.md)与轨迹复算通过；其 42.30 仿真秒仍耗时 282.49 墙钟秒，不能称为实时或人工验收通过。
- 2026-09-14，Astra ultra 根据真实动作干预确定单变量方案，Opus 实际编写 PPO 共同轮速均值策略。Codex 接入配对训练和评测，独立验证高斯概率、梯度及原版对照一致性。见[减速诊断与实验](d1_wheel_common_mean_study.md)；原始交付中的实机和裁剪表述错误也保留了修正记录。
- 同日继续按稳定直行、可靠越障、提高速度推进：Astra ultra 给出阶段验收和控制契约；实际 Opus 编写偏航消融 runner、仿真时间航向参考、松键制动核心和85维航向学习环境。Codex 负责物理闭环、集成及证据复算。制动候选增加坡上回退，保留原默认；新学习任务通过接口与训练试运行检查后，开始固定三种子的完整训练。见[驾驶优化记录](driving_optimization.md)。

## 责任与交付

| 工作 | 负责人 | 可验收交付 |
| --- | --- | --- |
| ATEC 课程迁移、训练任务与对照方案 | gpt-6-astra，ultra | 已核对课程来源、当前接口缺口、可执行任务卡；见[课程实施](atec_rl_curriculum.md) |
| 当前瓶颈、任务边界、实验矩阵及合并 | Codex | 明确问题、固定比较条件、采纳依据和 GitHub 提交 |
| 支撑转移、力分配、步态规划、残差控制等困难子问题 | Claude Opus | 数学假设、独立模块或小补丁、失败条件和可运行探针 |
| CLI 接入、简单修复、测试执行、日志和上传 | Codex 与脚本 | 实际输出、完整失败记录、来源和哈希 |
| 结果复算及风险检查 | 独立代理 | 不依赖实现者结论的复算或反例 |
| 操作体验验收 | 用户 | 对真实窗口的反馈；自动测试单列记录 |

Opus 可以承担算法实现和针对失败的改进，不局限于审核。简单渲染开关、导入修复或批量文件操作通常由 Codex 直接完成，更适合把 Opus 时间留给控制算法中的难点。

## 每轮协作流程

1. 先复现一个问题，保存基线、源码版本、最小输入和失败轨迹。区分物理失败、测试工具错误、显示性能和网络中断。
2. 写一张任务卡：目标指标、允许修改的文件、接口、固定参数、测试场景和退出条件。提供相关源码及证据，避免把整个仓库重复塞进上下文。
3. 让 Opus 交付一个能单独验证的候选。实现与独立检查分别分工，同一文件只有一个编辑者；现有正式实验的 77 个冻结文件和 25 个结果根不作为开发试验区。
4. 依次检查直接 CLI、最小动力学场景、必要对照和集成；早期失败先修复，再扩大测试。长任务期间继续做不依赖该候选的工作。
5. 用同条件结果决定采纳。速度提升同时检查漂移、接触、姿态、力矩和取消行为，不能用更改物理时钟或状态重置冒充控制改进。
6. 保存提示、实际模型与 session、输出、费用或用量（以实际返回字段为准）、本地修正和验收结论；中断时先恢复已有输出。及时提交已经通过的独立改动。

本机 Claude CLI 支持 `--effort`、`--max-budget-usd` 和 session 持久化。后续调用按任务复杂度选择投入并设置费用上限；小补丁采用较低投入，复杂步态问题才提高。额度不足时继续运行实验与集成，恢复前不反复试探。任务超出预估时先检查运行状态、输出和问题范围，再决定是否扩大投入。

## 后续任务优先级

v0.8 正式结果已发布并完成回下载校验。当前先完成 PPO 减速的配对实验，窗口的跳跃、台阶与侧步取消问题仍保留为待解决事项。随后按具体失败选择单个子问题：

| 顺序 | 任务 | 开始与采纳条件 |
| --- | --- | --- |
| 1 | 减小侧步纵向漂移和交接后的残余速度 | 先固定连续三步及松键后的完整轨迹；Opus 提出并实现有物理解释的候选，在左右和 90° 场景共同改善，保持落脚及力矩约束 |
| 2 | 梳理延迟失稳的控制原因 | 使用已有开发场景区分测量时序、估计误差和执行器延迟；明确假设后再试控制改进，不用正式 holdout 调参 |
| 3 | 扩展到低矮台阶或坡道步态 | 平地门槛满足后，单独实现接触平面和落脚可达性；先明确失败边界，再扩大场景 |

实习项目的研究主线仍是可复现的强化学习与控制实验。GUI 功能用于观察和验证，不无限挤占实验分析、迁移验证与成果说明的时间。
