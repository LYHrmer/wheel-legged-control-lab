2026-10-16 的新版入口恢复了本机 B22 准备链路：只接受已经逐项解释的源码和显示库更新，保留控制器、B22 权重与旧运行代码。新版还拒绝一种旧入口会返回成功的空跑：worker 退出码为 0，却从未报告 ready、没有执行控制。

## 使用入口

在本机仓库先做只读检查：

```bash
rtk proxy /usr/bin/python3 -B /home/lyh/wheel-legged-control-lab/scripts/play_b22_v27.py --check
```

输出列出三项明确迁移、排除的缓存路径、预期和实际核验字节数，以及全部未解释差异。`model_loads`、`gui_starts`、`physics_steps` 都应为 0。`--check` 不预约控制预算、不创建会话目录。

操作者实际需要运行时再使用普通入口：

```bash
rtk proxy /usr/bin/python3 -B /home/lyh/wheel-legged-control-lab/scripts/play_b22_v27.py

rtk proxy /usr/bin/python3 -B /home/lyh/wheel-legged-control-lab/scripts/play_b22_v27.py \
  --mode keyboard --seconds 60
```

固定脚本默认 `flat_1p6`，其余 `--profile`、`--actor`、`--mirror`、`--headless` 和键盘约束延续原入口。W 前进、Q/E 转向、Space/X 停止、R 仿真复位、Esc 退出；A/D 横移与跳跃仍未开放。每次正常启动使用新的结果目录及相邻 `_launch` 目录。

已有 v27 登记清单不需要重新生成。登记工具的 `--build-manifest` 是一次性版本发布操作，拒绝覆盖已有清单；日常只读检查也可直接使用：

```bash

```

## 成功需要有实际执行证据

旧 host 的反例已经用不导入模型的 `raise SystemExit(0)` worker 实际复现：预约 1,600 个控制拍、实际执行 0 拍，host 仍返回 0，且 `failure=null`、`execution_started_monotonic=null`。

新版退出检查还要求：

- ready、host、外层 supervisor 与 worker 收据齐全，并绑定同一 `session.json`。
- ready 的开始时刻与 host 一致，host 无源码差异、无遗留进程、预约已关闭。
- worker 无失败、无归档失败；固定脚本执行完整拍数，键盘会话执行至少一拍且不超过原上限。
- Python 控制完成数与实际 native 尝试/返回数一致，每控制拍五个 native 返回；缺失计数保留未知，不补零。

会话 `_launch/v27_completion.json` 保存判定和可观察计数。退出码为 0 或存在部分结果文件都不足以产生 `PASS`；该判定也不授予新的控制资格。
